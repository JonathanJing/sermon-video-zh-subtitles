# Apple 平台设计规范与同行的后续方案

核对日期：2026-09-12。这里区分 Apple 指导、当前源码事实和同行的产品建议；建议尚未实施。任务状态和进入条件统一维护在 [Backlog](BACKLOG.zh.md)，已完成的通用布局证据见 [适配记录](DUO-ADAPTATION.zh.md)。

## 一、Duo 设计要求提炼

| Apple 指导 | 同行采用方式 | 后续核验 |
| --- | --- | --- |
| 按可用空间和 size class 适配，跨显示屏保持功能、层级和状态 | 单栏突出当前中文字幕；宽窗口增加阅读栏，默认大纲、可切全文 | 840 pt 是项目暂定阈值，不是 Apple 设备规格；按实际可读宽度复核 |
| 标准 split view 在紧凑环境折叠，在宽环境展开；系统组件处理部分折叠避让 | 先保留 NavigationSplitView；正文和阅读模式使用现有模型 | 核对内屏单 App 与分屏下实际列宽和阅读锚点 |
| 系统导航、工具栏可转到侧边；顺序和操作可达性应保持 | 使用系统工具栏，按钮提供符号和标题；阅读切换留在其阅读栏附近 | 主播放与精调不能被溢出菜单隐藏到难以操作 |
| 前景遵守安全区域，分别处理各边 inset | 正文与按钮避开系统区域；背景可延伸 | 相机、灵动岛、键盘和另一 App 出现时都应重测 |
| 折叠时仅移动必要元素，避免剧烈重排 | 保留同一播放器与内容身份；控制不能横跨折叠区域 | 不把连续滚动全文人为切成“左右两页” |

规范依据：[Duo HIG](https://developer.apple.com/design/human-interface-guidelines/designing-for-iphone-duo)；尺寸与场景实现依据：[Prepare your app，2:46–8:08](https://developer.apple.com/videos/play/tech-talks/111461/)。

### 展开后的左栏：默认大纲，全文可切换

这是同行的产品决定：听众首先需要知道“讲到哪里、下一段是什么”，大纲占用的持续注意力较少。需要逐句理解、回看或对照英文时，再切全文。右栏始终承担当前中文字幕和主要播放操作，避免两处都在自动滚动。

大纲没有可靠章节时间映射时保持普通阅读；不凭来源段落索引推算音频进度。未来若加入“当前章节”，必须绑定同一来源与音轨时间轴，并区分人工审核与机器生成内容。

| 场景 | 拟采用布局 | 保留的行为 |
| --- | --- | --- |
| 外屏或窄分屏 | 当前字幕 + 播放；阅读 Sheet 提供大纲/全文 | 阅读选择、音轨和播放意图不变 |
| 内屏平展、空间足够 | 左侧大纲/全文，右侧当前字幕 + 播放 | 两种阅读位置分别保存；浏览不 seek |
| 像书本一样半折 | 优先让两栏分别落在可用区域 | 按系统区域调整列宽，按钮远离折叠处 |
| 放在桌面、上下分区 | 候选：上方当前大字幕，下方阅读与操作 | 先比较可读性和触达性；不是已批准的独立姿态 UI |
| 无障碍大字或可用区域不足 | 单栏、自然换行和滚动 | 不通过缩字强行保留双栏 |

Apple 的姿态建议是让内容与操作适应现有区域，并避免让连续滚动文章随着折叠过度位移；桌面姿态通常适合上方看内容、下方操作。以上具体内容分工是同行建议。[Strike a pose，1:29–5:12](https://developer.apple.com/videos/play/tech-talks/111463/)

### 工具完整后再实现的部分

截至核对日，[Apple 下载入口](https://developer.apple.com/iphone-duo/)仍将 Xcode 27.1 beta 标为本月稍后提供。已有 Xcode 27.0 和 iPad 测试只能验证通用自适应，不能关闭 Duo 专用任务。

- 安装可核验的 Xcode 27.1 beta 与 Duo runtime；记录 build、SDK 和 runtime 版本，使用进程级 DEVELOPER_DIR，不改全局选择器。通过 Device Hub 运行开、合、旋转与折叠。
- 核对正式 SDK 中 ReservedRegion、GeometryProxy 的区域查询和 ArrangementView 的可用版本与签名，再决定是否采用。相机遮挡区域与折叠分区不是同一种区域，不统一成固定中缝。
- 对比现有 NavigationSplitView 与 ArrangementView：前者承担导航层级，后者用于两个内容区的排列且不承担导航。只有实际姿态体验改善且状态连续性通过时才迁移，不为用新 API 重写界面。
- 核对侧边工具栏、轴向适配、visibility priority 和系统 overflow。系统侧栏与正文里的 PlaybackDock 分开验收，不能假设自定义播放栏会自动转到侧边。

API 与工具线索：[Prepare your app](https://developer.apple.com/videos/play/tech-talks/111461/)、[Strike a pose，6:39–14:21](https://developer.apple.com/videos/play/tech-talks/111463/)、[Raise the bar，2:00–13:10](https://developer.apple.com/videos/play/tech-talks/111462/)。这里记录的是官方介绍的待核验入口，不是本机 SDK 接口验收。

## 二、灵动岛与 Live Activities 规范提炼

系统 Now Playing 和自定义 ActivityKit 不是同一条实现路径；灵动岛也不是 App 可自由占用的第二块屏幕。具体展示由系统按设备、活动竞争和使用场景安排。

| Apple 指导 | 同行约束 |
| --- | --- |
| 活动应有明确起止，只展示值得快速一瞥的信息 | 不展示全文、大纲或逐句翻译流；活动状态来自实际业务状态 |
| 支持 compact、minimal、expanded 与锁屏展示 | 每种尺寸独立设计信息密度；不能只做展开图 |
| 点击应直达相关内容；交互宜简单且少 | 默认点击回到对应收听/对齐上下文；最多优先验证一个必要快捷动作 |
| 更新有新信息才发生；结束后及时 end | 进度使用系统时间视图；事件变化更新，数据过期明确降级 |
| 内容清晰、紧凑、边距与轮廓协调 | 关键状态用易读字重，同行绿用于识别，不只靠颜色区分状态 |
| 尊重用户关闭和敏感信息展示选择 | 不擅自重建用户关闭的活动；考虑隐藏证道标题与讲员的选项 |

以上依据 [Live Activities HIG](https://developer.apple.com/design/human-interface-guidelines/live-activities)。HIG 页面正文通过 Apple 官方文档 JSON 核对，网页抽取器的 JavaScript 提示不作为内容证据。

视觉补充：紧凑视图两端应成为一组信息，展开时保持元素相对位置；避免空白撑宽、长标题拥挤和复杂装饰。黑色灵动岛中的内容不套用 App 正文玻璃效果。锁屏和 StandBy 分别检查对比度、圆角内边距与放大资产，Always-On 低亮度状态下不能依靠动画传达信息。[Design dynamic Live Activities](https://developer.apple.com/videos/play/wwdc2023/10194/)

工程边界：活动最长活跃 8 小时，结束后的锁屏停留与活跃状态分开；静态与动态数据合计不超过 4 KB；活动扩展本身不能直接联网或取得位置更新。它不授予 App 持续采音、匹配或后台执行能力。按钮使用 App Intents 路径，不能直接在 Widget 中新建播放器。[ActivityKit：Displaying live data](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities)

## 三、同行怎样利用灵动岛

### 推荐方向：媒体播放由系统承担，专属活动先证明增量价值

普通收听主要需要标题、进度、播放/暂停，这些先交给现有 Now Playing。自定义 Live Activity 的更有价值候选是用户主动开始的“同一录音对齐会话”，向用户说明正在做什么、是否得到可靠结果，并提供回到精调的入口。是否默认开启，应先比较有无自定义活动的实际体验。

一个重要限制：目前采音只有约 8 秒，切后台即取消。若用户始终停留在 App，直接显示 App 内对齐状态已经足够；不能为了让灵动岛有内容而延长采音、绕过后台限制或声称后台匹配可用。对齐 Live Activity 的启用以合法且确有价值的后台流程验收为前置条件；否则只保留系统媒体体验和 App 内状态。

以下为候选内容契约，不表示现有功能：

| 展示形态 | 普通收听 | 对齐会话候选 |
| --- | --- | --- |
| Compact | 优先使用系统媒体展示 | 一侧简洁状态符号，另一侧短状态或真实采样剩余时间 |
| Minimal | 由系统管理媒体状态 | 一个可识别的阶段符号；VoiceOver 朗读完整状态 |
| Expanded | 不重复堆叠第二套播放器 | 简短来源标题、采音/匹配/结果；至多一个“取消”或“查看结果”动作 |
| 锁屏 | 原有媒体控制 | 比展开略完整的说明，敏感标题可隐藏；不显示全文 |
| Duo 侧边区域 | 接受系统调度 | 与系统工具栏竞争空间时仍可辨认，不能挤掉必要播放操作 |

对齐状态要用事实命名：

- 采音中：只在麦克风实际运行时显示；权限失败、取消或切后台后立即退出。
- 匹配中：本机正在处理已采样数据，不等于继续听现场。
- 匹配成功：仅表示找到同一录音位置。只有来源/音轨映射校验通过并实际定位后才能显示“已定位”。
- 定位后：显示“本次定位完成”或最近定位时间，不显示“持续同步正常”；现场继续重放并不会被自动验证。
- 失败或过期：保留原播放位置，提供回 App 手动精调；不为了刷新活动而再次采音。

点击活动只导航，不自动切音轨或 seek。后续若增加“撤销定位”，应校验会话和来源、期间无新手动操作且事务仍有效；先在 App 内验收，再考虑作为唯一快捷动作。普通收听、下载或每句字幕变化不触发提醒声，这也是教会收听场景的产品选择。

### 当前源码与缺口（本次只读核对）

| 已有实现 | 尚缺的产品能力或证据 |
| --- | --- |
| 系统媒体已有播放/暂停、前后 1 秒及拖动定位；另有自定义活动 | 系统媒体尚无品牌封面图片；两路输出的实际展示与重复程度需真机对比 |
| ActivityKit coordinator 与 WidgetKit 四种基础展示；普通前台播放会请求活动 | 默认是否需要和系统媒体展示重复，尚无实际体验对比 |
| 状态包含标题、讲员、位置、时长、播放/缓冲及语言 | 没有对齐阶段、来源验证结果或对应会话身份 |
| 事件变化更新，播放期间另有约 15 秒更新；播放 staleDate 为采样后 45 秒 | 这些是源码策略，不是系统刷新时效保证；需测挂起、缓冲和低电量下的过期展示 |
| 用户移除后抑制同一来源重建；换源、结束和冷启动清理旧活动 | App 内独立开关、长暂停的退出策略和异常生命周期测试仍待补齐 |
| widgetURL 为 tongxing://listening，视图没有 Button/Toggle | App 只注册 URL scheme，没有 onOpenURL 路由；尚无来源校验或 LiveActivityIntent，点击与 Sheet/场景恢复需验收 |
| 黑色锁屏卡、绿色符号，基于时间区间的进度 | Duo 侧边、Always-On、StandBy、长英文、VoiceOver 和多个活动并存的真实展示未验收 |

## 四、落地顺序与完成标准

先完成可独立推进的系统媒体/Live Activity 对比、状态语义、深链和生命周期测试设计；Duo 工具发布后完成 SDK、侧栏、reserved regions 和姿态矩阵；最后使用实体设备验证声音、锁屏和跨场景状态。普通 Live Activity 的现有 SDK 工作不必等待 Duo，Duo 侧边专项验收必须等待相应环境。

任务仅在有代码、匹配的测试与实际系统展示证据后关闭；需要后台能力的任务还必须有真实后台执行证据。源码存在、编译成功、UI 测试通过、真机展示通过分别记录，不互相替代。详细依赖和交付条件见 [Backlog](BACKLOG.zh.md)。
