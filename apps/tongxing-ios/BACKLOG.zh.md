## UPSTREAM-P0：英文逐字稿、词级时间轴与自然语速

这是内容生产依赖，不由 iOS 播放器补救。每周正式多语言内容必须先冻结批准原声窗口的英文逐字稿，再完成词级时间轴和缺口审核，随后才生成各目标语言的逐句完整翻译与音轨。任何英文未覆盖、低置信对齐未审核、目标语言静默删义或自然语速无法容纳的段落都阻止发布；客户端不得通过自动加速、拉伸或裁切绕过。详细顺序与验收见[工作流 P0 门槛](../../docs/workflows/README.zh.md#预制播放质量门槛2026-09-20-现场反馈)，第一阶段代码见[英文逐字稿与词级时间轴 POC](../../experiments/english-word-timeline-poc/README.zh.md)。

完成定义：代码级发布阻断器已接入，且至少一篇真实证道在同一录音正常 1 倍速下完成全篇英文覆盖、词级对齐、目标语言完整性、自然语速和实体设备播放听审。在此之前，该项保持 backlog，不能因单元测试、文件可播或指纹定位通过而关闭。

## DISCOVERY-01：Gemini 音视频 sidecar 隐形辅助标注

结论：暂不接入生产流程。真实全篇测试覆盖 1,940 秒证道、411 个句子候选和 39 个音视频窗口；Gemini 生成的候选经 GPT-6 Astra 盲审后，321 句标注获支持、29 句不支持、61 句不确定。`explanation` 候选相对可用，但 `transition`、`other`、混合经文／解释句、经文引用及未覆盖句仍不足以成为生产依据。完整数据、已知误差和产物边界见[全篇 sidecar 结果](../../experiments/omni-annotation-poc/FULL-SERMON-RESULT-2026-09-20.zh.md)。

在本项晋级前，sidecar 只能作为可丢弃、失败开放的外部审阅层：不得改写或阻断英文逐字稿、词级时间轴、翻译、配音、语速、字幕切分和发布状态；模型候选不得自动成为人工 Gold，也不得因 GPT-6 裁判支持而标记为人工审核。

后续优化与验收：

- 由操作员在移动审阅页听完全部 39 个窗口，并对 411 句逐句接受、修正或标记混合／不可辨，形成绑定媒体哈希、时间轴和 schema 版本的人工 Gold。
- 分别统计 `scripture_reading`、`explanation`、`transition`、`other`、混合句及未覆盖句相对人工 Gold 的准确率、召回率和混淆；不能用总体数字掩盖弱类别。
- 优化重叠窗口合并、边界覆盖、停顿提示、经文出处核验和“一句含多种事件”的表达；候选仍须与冻结英文词级时间轴对齐。
- 在同一冻结语料上复跑并保留模型、提示词、输入媒体及输出哈希。只有预先约定的各类别门槛均通过，失败路径保持不影响正式生产，且人工听审确认确有净收益，才另行提出受控生产试点。

## IOS-01：灵动岛与锁屏

目标：收听或短时对齐时，离开 App 仍能看见当前状态并快速回到操作。ActivityKit／WidgetKit 基线已存在，下列项目作为补齐与验收要求，不另建重复实现。

- 播放场景先检查现有 `MPNowPlayingInfoCenter` / `MPRemoteCommandCenter` 的系统媒体体验，补齐标识图片、标题、进度及播放状态同步。系统媒体区域的布局由系统决定。
- 如需展示“正在听现场 / 正在匹配 / 已对齐”等专属信息，沿用现有 ActivityKit + WidgetKit 扩展。紧凑视图显示标识与状态，展开视图显示证道、进度及适合的操作；不把整段双语字幕塞入灵动岛。
- 所有操作仍交给唯一的 `PlaybackController`；Live Activity 只是状态与操作入口，不另建播放器，也不充当后台运行保证。
- 暂停、换篇、播放结束、对齐取消/超时后更新或结束对应状态；不支持灵动岛或用户关闭实时活动时，保留正常 App 和锁屏媒体操作。

验收：实体 iPhone 检查紧凑、展开、多个活动并存、锁屏及横屏展示；播放/暂停/定位与 App 一致，无重复或过期活动。具体可用布局按实际系统验证。自定义活动须覆盖所需展示形态，依据 [Apple Live Activities 文档](https://developer.apple.com/documentation/ActivityKit/displaying-live-data-with-live-activities)。

## IOS-02：同一录音重放，一键指纹对齐

**当前范围：只考虑同一份英文录音重放，正常1倍速。** 本版采用与已发布 Web 内容共用的版本化指纹索引和纯 Swift 本机匹配器，暂不开发 ASR、关键词、重新讲述或视频画面匹配。完整分析、现有数据证据、时间补偿和实验步骤见 [音频指纹对齐方案](FINGERPRINT-ALIGNMENT.zh.md)。

用户点击“听现场并对齐” → 短时采集英文 → 本机匹配录音位置 → 校验目标音轨及时间原点 → 自动定位中文 → 关闭麦克风并恢复播放意图。支持取消、超时、失败回退和撤销；切后台会取消本次采音并恢复此前播放意图；后台继续匹配尚未实现，不持续监听。

首版优先使用按英文时间轴布置的中文同步音轨。已有同步候选制作链路可复用；普通自然语速音轨不能直接用英文秒数定位。指纹可以先独立实验，不以完成双语全文或现场 ASR 为前置条件。

主要交付：

- 为每篇英文参考录音生成指纹目录，并发布绑定来源、时间原点、目录哈希和中文音轨哈希的版本化能力清单；下载后可离线使用。
- 验证当前同步候选的时间原点及放置质量，保留审核状态；不因声学指纹成功而宣称英中语义同步已通过。
- 本机短时采音与匹配，记录采样时钟并补偿处理延迟；iOS 17 不依赖 iOS 18.4+ 才提供的 `confidence`。低置信或位置不唯一时保持原进度。
- 所有退出路径关闭采音；换篇、换轨或手动操作使旧请求失效，迟到结果不覆盖用户操作。日志不默认保存现场录音。
- 分别验证文件匹配、扬声器到手机的声学匹配、中文实际播放位置以及后台执行；记录成功率、拒绝率、误跳率、位置误差与总耗时，不把模拟器或文件成绩当成现场证明。

来源块关联的双语全文基线已由 IOS-04 接入，完整平台验收仍待完成；自然音轨的更细跨语言映射留到后续需求。远场 AGC、同一次 10→15 秒自适应采集及近／中／远 A/B 仍按 `DEV-FIELD-001` 实施，不因现有文件指纹匹配通过而关闭。

## IOS-03：多语言界面、内容与音轨

Layer 4 的发布接口、目标语言选择、界面语言切换、跨语言音轨标注、catalog adapter、离线身份和完整验收拆分见[多语言 Layer 4 发布与 App 改进 Backlog](../../docs/multilingual-layer-4-delivery-app-backlog.zh.md)。该设计以 `pageId + targetLocale` 为发布边界，App 内将 `interfaceLocale`、`contentLocale` 和 `audioLocale` 分别管理。

已完成的界面基线：可选择跟随系统、简体中文、English、한국어、Español、Tiếng Việt；界面切换不隐式改变证道内容、音轨和进度。已有 String Catalog 与偏好保存。五种界面选项不等于五种完整证道音轨，也不代表已完成母语、长文本和 VoiceOver 验收。

界面语言、字幕语言、音轨语言分开管理。切换到英文界面不隐式更换正在播放的音轨，也不将中文内容反译后称为英文原文。已有英文原文与原视频入口；英文原声作为独立可缓存音轨的完整支持仍须有来源音轨、时码与完整性证据后才能开放，不能把界面切换或视频链接当成已具备英文音频。

已完成的内容消费基线：正式 v3／v2 reader 已接入中文（`zh-Hans`）、西班牙语（`es`）与韩语（`ko`）的已发布内容和同语言音频，支持默认选篇及自动准备音频。两种新增目标语言仍须直接从冻结、词级对齐的英文源生成，不以中文为翻译中介；每种语言分别保存模型／人工审核状态、来源映射、音轨时间轴、哈希与可用能力。某语言只有界面翻译、只有文本或只有音轨时，目录和 UI 必须准确显示该能力，不笼统标记为“已支持”。

剩余合同与验收：

- catalog 和离线缓存按 BCP 47 语言标签声明每周可用的文本、字幕与音轨；未知或旧目录继续回退到实际已有语言，不串用不同语言的哈希、进度或时间轴。
- 语言选择器只列出本周真实可用内容；切换西班牙语或韩语后，标题、全文、字幕高亮、下载、恢复、锁屏／灵动岛元数据和 VoiceOver 使用相符语言。
- 西班牙语、韩语各至少用一篇真实证道完成英文源覆盖审核、目标语言内容审核、整篇音轨解码／听审、正常 1 倍速同步检查、离线下载恢复和实体设备播放，才可把对应能力标记为可用。
- 缺少某种语言时显示明确回退及当前实际语言；不把机器翻译候选称为人工审核，不因另一语言通过而继承其批准状态。
- 自动化测试覆盖语言能力组合、回退、切换后进度隔离、离线缓存、长文本布局、VoiceOver 语言和旧 catalog 兼容；真实内容质量与语速仍由各语言独立人工听审。
- 单独证明跨轨 source-unit 定位及 `PlaybackHistory` v2 的完整身份与恢复合同；不能从已有下载缓存或语言菜单推断这两项全部完成。

界面本地化验收：完整核心收听/下载/恢复/精调流程无遗漏硬编码文案；切换和重启后符合所选语言，进度与缓存保持；各语言长文本、日期、数字、较大字号、VoiceOver 及灵动岛分别检查。界面本地化与内容／音轨能力分开记录；未提供某语言的界面或内容时明确显示实际语言和回退情况。

## IOS-04：字幕全文中英双语

目标：全文每个对应内容单元先显示中文，再显示英文原文。英文使用更小的动态字号和可适应深浅色的次级文字颜色；与中文形成层级，同时保持可读性，不能只靠颜色辨识语言。来源块关联和 v3 双稿阅读基线已接入，以下完整验收不因已有实现或定向 UI 测试而关闭。

- 通过来源段落/单元关联显示，保留一对多、多对一和缺失状态；不能按两个文本列表的行号拼接，也不能把中文回译成“英文原文”。
- 英文缺失时标记“英文原文暂缺”，保留中文和播放；整篇缺失时避免重复堆叠提示。英文来源和审核状态保留，不因展示为双语升级为人工审核。
- 当前中文音轨仍决定全文高亮与时间按钮；点击时间只触发现有定位。英文源视频时间如需展示，须与当前中文播放时间明确区分。
- 完整英中内容关系随离线资料缓存；缺少新增字段的旧目录保持可读，来源/音轨切换后不串段。

验收：抽查首段、中段、末段、重复经文、一对多及缺失案例；中文在上、英文在下且更小、颜色不同；深浅色、增强对比、大字、窄屏与横屏不截断；VoiceOver 按中文后英文顺序并使用相应语言朗读。全文滚动、回到当前句、时间定位及离线读取保持有效。

## IOS-05：iOS 选篇与 Firebase App 对齐

目标：iOS 与 Firebase App 对同一份正式 `multilingual-v3.json`／v2 Release 显示一致的已发布页面、默认页和每页可选语言；保留 `multilingual-v2.json`／v1 Release 的旧站兼容。选篇以 `pageId` 为身份；同一天的多个片段仍是不同页面。旧 `weekly.json` 中文周次继续可选，但不能成为新多语言页面出现的前提。Firebase Dev 的机器 POC 页面与正式已审页面须明确区分，不能在 iOS 正式选篇中混作已发布内容。

- 核对 v3 优先、仅 HTTP 404 时请求 v2、按版本缓存与坏缓存回退；无效 schema 或哈希不能视为已验证发布。在线、离线、旧站和缓存损坏分别保留测试证据。
- 核对两端的页面顺序、日期／标题／讲员、当前页标记、默认页、语言能力和不可用状态；界面语言不改变已选内容语言或音轨语言。
- 从 Firebase 深链 `/pages/<pageId>/<locale>`、旧 `?week=<pageId>` 及 iOS 入口进入时，落在同一 `pageId + targetLocale`；无效或撤回目标按目录规则明确回退，不打开另一篇的缓存页面。
- 切页时隔离播放进度、下载、字幕与声纹请求；保留用户在每页明确选择的语言。目录刷新或离线恢复后仍按当前发布哈希核对，不沿用已撤回或不匹配的页面。
