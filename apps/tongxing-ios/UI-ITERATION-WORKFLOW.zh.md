# 同行：以 Xcode 为主的 UI／UX 迭代流程

[English](UI-ITERATION-WORKFLOW.md) · [iOS 设计约定](DESIGN.zh.md) · [开发与验证](AGENTS.md)

决策日期：2026-09-30。**iOS 是主要体验，Firebase 托管的浏览器客户端为辅；当前流程不使用 Figma。** 本文记录已确定的工作方式，不代表已实现预览自动化、修改 UI、完成测试或发布。

## 1. 在实际 App 中设计

排版、文案、控件和小范围交互调整，直接在 Xcode 中修改现有 SwiftUI。已有合适样本时，用 Canvas／Previews 查看局部；完整流程在 iPhone 模拟器验证，设备相关体验在真机验收。Apple 的预览是随代码更新的交互视图，不是独立设计稿：[Previews in Xcode](https://developer.apple.com/documentation/swiftui/previews-in-xcode)。

在开发 Mac 的仓库根目录打开已有工程：

```sh
open apps/tongxing-ios/Tongxing.xcodeproj
```

优先查看 `App/ContentView.swift`、`App/PlaybackDock.swift` 和 `App/DesignSystem.swift`。复用 `AppModel` 与既有 `PlaybackController`，不能为了截图另建播放器或重复状态。依赖模型的视图可能需要样本数据，打开文件不等于预览可用；不能为了建立新预览系统阻塞小改动，先使用可运行的模拟器。

设计基准是**已确认的 iOS revision、实际截图及交互规则**，不是无版本的图片。SwiftUI 定义实现，既有设计约定定义共同意图，截图只证明被捕获的状态。系统材质、安全区、Dynamic Type 和无障碍优先于固定像素一致。

## 2. 小改动闭环

**截图／批注 → 小范围 SwiftUI 修改 → 构建与实际操作检查 → 独立审核及 iOS 确认 → 判断网页适用性 → 按需适配网页 → 获授权的每周发布。**

| 步骤 | 动作与退出证据 |
| --- | --- |
| 提出需求 | Jonathan 提供编号截图和预期结果；UX 补充“当前状态 → 操作 → 预期结果”。Codex 记录页面和不得改变的行为，按既有规范决定常规间距，不逐项索要像素值。 |
| 建立基线 | 读取当前分支、差异和目录约定，从当前 `dev` 建独立分支，不修改其他并行分支。先复现相关状态，记录改前 commit。 |
| 原生迭代 | 只修改受影响的 SwiftUI、组件和本地化文案；使用相同内容、设备配置和状态返回真实前后截图。生成效果图不算执行证据。 |
| 检查与审核 | 运行定向检查，保留失败和跳过项；由独立审核者只读检查精确 revision。实现者修复并重跑受影响检查；审核者不能自己修改后自行批准。 |
| iOS 确认 | Jonathan 或明确委托的人确认精确 revision 与交互改动，机器审核不能代替人审。未变化证据不重复索要批准；实质改动只使受影响验收失效。 |
| 网页判断 | 记录 `required`、`not_applicable` 或 `deferred` 及理由；延期项关联后续任务。iOS 基准确认后再适配。 |
| 发布候选 | PR 附证据、独立审核状态、网页处理决定和剩余缺口。每周汇总已确认改动；合并、TestFlight 分发和生产部署仍分别按授权执行。 |

保持有界返工：任务记录修复上限，默认两轮定向修复。用尽后保留最佳已验证版本，说明具体阻塞点，不无限重做或悄悄扩大范围；阻塞项可转入下一候选，不拖住无关已通过改动。这是协作规则，不是新增生产调度器、模型策略或 RQC 实现。

较大的导航重组或全新多页面功能，先补有范围的交互方案；不因此自动引入 Figma 或其他设计工具依赖。

## 3. 证据与按风险验证

用户提供问题，不负责填写测试表。Codex 在 PR／任务中补齐简短记录：

| 记录 | 最少内容 |
| --- | --- |
| 身份 | 任务／批注编号、基线与候选 commit、App build 身份、受影响文件。 |
| 复现 | 设备类别、OS／Xcode、方向、明暗外观、界面／内容语言、字号、样本／内容身份、播放／下载状态及操作步骤；公开记录不含私有设备唯一标识。 |
| 结果 | 前后截图、命令与退出码、实际通过／失败／跳过数、独立审核结果、人工确认记录、未完成检查；未执行写 `not_run`。 |
| 网页交接 | 已确认的 iOS commit 与截图引用、共同改动意图、允许的平台差异、浏览器验证范围与结果。 |

复用合成或已授权样本，不把私有证道、个人数据、凭据、录音或原始日志提交 Git。截图／构建输出保存在忽略目录 `artifacts/tongxing-ios/<日期>/...`；仅将脱敏证据附到获授权的 PR 或产物存储。本地路径不等于审核者可访问的附件。不得覆盖旧证据，也不得换个 commit 标签冒充新结果。

UI 改动先构建，从当前源码选择相关 `TongxingUITests`，并实际操作受影响交互。使用已有 [scripts/ios.sh](scripts/ios.sh)，命令和共享模拟器约定仍以 [AGENTS.md](AGENTS.md) 为准；`launch` 只运行已有构建，不会自动重建。操作前查看最新 UI 层级，布局变化后重新读取。按实际可用的本地工具执行，缺少模拟器／工具连接时如实报告，不声称已远程截图。截图输入方式参考 OpenAI 的 [image-input guidance](https://learn.chatgpt.com/docs/image-inputs)。

受影响布局检查长字幕、小屏、大字、浅／深色；按改动补横屏、减少透明度、对比度、VoiceOver／焦点和较长本地化文案。交互改动必须操作验证，不能只凭静态截图批准。明确实际平台覆盖；缺少必要证据阻塞对应验收，不阻塞无关工作。

除明确要求外，保持播放意图／位置、音源、下载／哈希完整性、字幕同步、界面语言与音轨语言语义、来源／审核声明、隐私／统计选项及麦克风权限不变。“外观改动”也可能通过菜单或控件影响行为；触及这些边界就运行相关播放器／存储／Core 检查。不能为调整 UI 重跑 ASR、翻译、TTS、完整视频生产或付费模型阶段。

## 4. 浏览器适配，不是像素复制

辅助客户端指 **Firebase 托管的 Web UI**；Firebase 内容托管与客户端优先级是两回事。Codex 依据已确认的 iOS 截图、交互说明和语义样式修改现有网页实现，不只看一张图。不假设 SwiftUI 自动转网页，也不假设截图能表达响应式规则。

统一品牌、术语、信息层级、主要操作强调和真实状态文案；保留浏览器的响应式布局、语义控件、键盘／焦点、滚动及能力降级。不要照搬 iPhone 系统外框、系统弹层或原生专属能力。受影响页面检查移动 Safari 与桌面浏览器，记录实际浏览器／视口及缺口，保留支持范围内的非 iOS 访问。

文字层级变化可能需要适配；原生系统工具栏调整可以标记 `not_applicable`。网页只有验证过相应能力，才能显示类似原生的成功状态，尤其是离线／下载或后台播放；共享文案须符合各平台的真实行为。

保持 catalog／release schema、不可变内容身份、URL、哈希和已有客户端兼容。纯外观网页跟进不必阻塞独立兼容的 iOS 发布；共享合同变更或明确绑定的发布计划，必须走相应跨端门禁，不能用视觉确认豁免。此流程不授权修改上游内容或部署。

## 5. 每周交付与发布边界

周内收集小需求并完成短闭环，每周冻结候选后做适用的发布回归。分别记录原生构建／测试、人工 UI 确认、真机验收、浏览器检查、TestFlight、App Store 审核、网页部署和现场验收。复用未变化的有效证据，剩余发布事项按 [RELEASE-READINESS.zh.md](RELEASE-READINESS.zh.md) 核对，不沿用历史测试数充当本次结果。

仅文档变更不会交付新 UI。打包在 App 内的 SwiftUI 改动需要新构建，Firebase 部署不会更新已安装的原生 SwiftUI。App Store 新版本需审核，外部 TestFlight 可能需 Beta 审核；每周迭代是目标节奏，不保证某天获批。参考 Apple 的 [App Review 概览](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/overview-of-submitting-for-review/) 与 [TestFlight 概览](https://developer.apple.com/help/app-store-connect/test-a-beta-version/testflight-overview/)。

获授权发布前，记录候选 commit／build 和已知可用回退基线。代码 revert 仍需新原生构建及相应分发／审核，不能承诺立即回滚用户已安装的 App Store App。网页回退需保持内容兼容并遵守部署授权。避免在主日聚会窗口临时试验 UI。

