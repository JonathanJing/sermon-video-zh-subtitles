## 训练什么

先建立每位讲员的声音档案，再决定是否微调。参考音频克隆只在推理时提供一小段原音；微调则会更新模型权重。两条路线分别保留基线与输出，不把保存参考音频或生成 MP3 称为“训练完成”。

推荐起点仍是 Qwen3-TTS Base。官方目前提供**单讲员**微调：训练数据包含目标音频、对应转写与同讲员参考音频，经 speech tokenizer 转为音频 codes 后执行 SFT；微调出的声音以独立 speaker 名称推理。[官方训练说明](https://github.com/QwenLM/Qwen3-TTS/blob/main/finetuning/README.md)

每位讲员一个数据集和 checkpoint。先挑一个讲员试验，不把不同讲员的音频混入同一个单讲员训练任务。

**英文录音必须配英文逐字稿。** 中文译文用于之后的中文语音合成与评估，不能用“英文声音＋中文译文”作为同一训练样本。英文音色微调是否损害基座的中文发音、音色迁移与自然度，需要中文固定测试集回答。

## 从视频/音频到可训练样本

1. **确认主素材和去重。** 固定原视频/音频 hash、证道窗口、来源与允许用途。按媒体 hash 去重复副本，再按转写相似度和音频匹配识别不同 URL 下的同篇证道；同一礼拜完整录像与其剪辑版要保持相同分组。
2. **区分说话人区间。** 先用 `pyannote/speaker-diarization-community-1` 建立 `SPEAKER_00/01` 时间区间，再由人工把匿名区间对应到讲员身份。模型可以区分“谁在何时讲话”，不能凭其输出识别真人姓名。该模型的访问条件需按模型页处理；本次未下载、未接受访问协议。[官方模型页](https://huggingface.co/pyannote/speaker-diarization-community-1)
3. **提取干净讲话。** 交叉使用说话人区间、VAD 与人工试听，排除音乐、掌声、群体回应、串话、剪辑转场、严重混响、饱和与过低音量。首轮尝试 4–15 秒完整语句，保留句首句尾的自然余量；这只是实验采样范围。
4. **转写与真实对齐。** 已有英文是候选文本。缺漏部分用现有 ASR 路径校正；`Qwen3-ForcedAligner-0.6B` 用相同语言的英文文本与英文音频定位，再由真人听原音确认。不能把阅读稿估算时间作为精确切点。
5. **逐段准入。** 记录讲员确认、声音使用范围、转写审核、音频质量与来源 hash；不清楚的段留在待审区。音频中的实际措辞与语气保留，不把更顺的英文改写稿当作逐字训练标签。
6. **按整篇证道划分。** 同一篇、同一录音的相邻片段和重复剪辑必须在同一个 split。训练/验证/测试按完整证道分开；样本少时先收集，不能随机拆邻接句来制造验证收益。现有 `untouched_test` 始终保持独立。
7. **冻结参考音。** 从训练分区选同一讲员、已准入的干净参考音；记录 hash。验证/测试音频不能偷偷作为训练参考。所有训练条目可复用该固定 reference。

拟议目录：

```text
artifacts/sermon-dubbing/speakers/<speaker-id>/
  speaker-profile.json          # 姓名依据、匿名说话人映射、允许用途
  candidates.jsonl              # 未正式准入候选，不进入生产训练器
  reviews.jsonl                 # 真人逐段审核与证据
  train_raw.jsonl               # 准入后的英文音频/英文文本
  validation.jsonl              # 不同证道
  heldout.jsonl                 # 冻结测试，不用于挑 checkpoint
  reference.wav
  audio/<source-id>/<clip-id>.wav

```

官方训练器输入形如以下内容；**这只是字段示例，当前不存在这些已准入文件**：

{"audio":"audio/source-a/clip-001.wav","text":"Exact English words spoken in this clip.","ref_audio":"reference.wav"}

## 小规模训练的顺序

先以一位讲员 **20–40 分钟已准入的干净语音**作为可行性试验目标；这不是模型最低要求，也不保证能提升。如果只有单篇素材，最多报告训练工程 smoke，不能证明泛化。

1. 固定未微调 Base 的中文测试输出，保存相同参考与参数。
2. 在隔离环境将英文训练音频编码。官方示例入口是 `prepare_data.py` 与 `Qwen/Qwen3-TTS-Tokenizer-12Hz`。
3. 从 `Qwen/Qwen3-TTS-12Hz-1.7B-Base` 做单讲员 SFT。第一轮可从 batch 1、学习率 `2e-6`、1 epoch 起，记录显存/统一内存、loss、耗时与 checkpoint；小 batch 的参数需要本机实测，不能照抄官方 batch 32。
4. 只在验证集决定是否增加到 2–3 epoch。训练完成不是声音质量通过，不按最低训练 loss 自动选出成品。
5. 用固定中文测试稿比较未微调/微调声音，测试经文与专名、长句、多层引语、温和/强调语气以及连续 10 分钟。相同中文文本、采样参数、后处理与播放音量下匿名试听。
6. 最后才跑冻结测试，记录中文可懂度、相似度、读错/漏读/重复、长段断裂与听觉疲劳。中文能力退化时保留 Base 或重做数据，不能因为“更像原讲员”而接受内容错误。

DGX Spark 已完成本次工程试跑，使用已有 NVIDIA PyTorch 26.06 镜像与新建的独立 venv。资源上限设为 32 GiB 内存、6 CPU；未停止已有服务。运行采用 SDPA，修正可选 25Hz 模块过早导入依赖的问题并使用 stdout 记录 loss，所有适配与失败日志均保留。训练约 70 秒；具体依赖与 checkpoint hash 见实测报告。

本次工程试跑明确使用 `research-inputs.json` 声明候选来源、允许用途、单篇局限和 `productionTrainingAdmission=false`。候选没有被重标为人工 Gold；`trainingAdmittedCount=0` 仍表示没有正式审核准入的样本，实际执行过的工程训练样本另记为 21。生产训练扩大前，要完成逐段审核并增加不同证道的验证资料。后续三篇扩充仍采用明确标记的独立工程候选试跑；63 条实际工程训练样本另记，不自动晋升正式准入。

## 中文流畅度首先解决的事

声音训练主要解决“像谁”；中文是否顺畅还取决于翻译、断句、发音、TTS 和播放策略：

- 用完整语义单元写口播稿，保留上下句指代与论证；不从大纲生成看似完整的配音。
- 避免每条短字幕单独合成。先比较完整句子与 2–4 句连贯分组，句子内部不随意硬切。
- 经文数字与专名建立可听表达/发音表；发音控制只能用所选模型实测支持的语法，不能把拼音标签原样念给会众。
- 保留原生语音、分段文件与生成参数；一次性装配成连续 MP3。网页播放一个 MP3，避免浏览器逐个拼接小音频产生接缝。
- 先确认自然语速，再做小范围时长适配。前进/后退微调只改变音频位置，不能修复漏读、语义错位或持续的速度差。

本次 POC 的口播文本共 398 个字符（含标点和数字），来自 2026-08-23 的阅读稿 blocks 9–10。文本保持一致，只改变分组方式：第一轮 4 组与 14 句，第二轮缩短分组预算后为 5 组与 14 句，段间均额外留 0.18 秒。当前连贯版 107.20 秒，逐句版 103.38 秒；未变速，也没有为凑时长裁切语音。

第一轮连贯版的“挣扎”收尾在两次回转写中可疑；第二轮回转写已包含完整词，但还标出了专名与“作出的”中“的”的差异。不能直接把 ASR 差异认定为 TTS 错读，也不能据回转写一致判定口播自然。下一次试听重点是句末收尾、专名、段间音色/节奏，以及连续听是否疲劳。

## Firebase 发放

用户已要求推进部署，当前每周应用已上线独立 Firebase Hosting 站点，使用 `sermon-weekly-catalog-v1` 清单。小规模中文样片直接由 Hosting 发放；整篇与长期归档可改为 Cloud Storage 放不可变 MP3，清单仍保留稳定的周次/音色/字幕接口。音频不进入 RTDB。[Cloud Storage 下载机制](https://firebase.google.com/docs/storage/web/download-files)

发布包须记录 MP3 hash、来源视频/剪辑版本、实际对齐状态、片头偏移和审核状态。前端先加载音频元数据/缓冲，由用户点击开始，保留播放/暂停、前后 5 秒与 ±1/±0.25 秒微调。微调属于各设备本地状态，不广播给其他听众。

Cloud Storage 文件访问按最终发放范围设置，下载 URL 不等同于永久私密链接。当前已上传中文样片及 UI，没有上传原音/训练集或修改数据库规则。线上 Range 和浏览器播放已验证；手机锁屏、网络中断、耳机延迟、不同设备漂移和整场同步仍需另验，下载/播放器按钮可用不等于会场同步已通过。
