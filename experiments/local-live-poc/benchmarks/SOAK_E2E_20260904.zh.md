## 基线暴露的问题

1. 浏览器开启回声消除和降噪时，会把扬声器/音响中的目标人声当作回声削弱，并在音乐或弱残留区段大量产生 `The.`。
2. MLX 对部分弱声片段不返回 final；客户端固定额外等待 5 秒，使单次空片段放大为 6–8 秒字幕长尾。
3. MLX server 退出后没有监督器，Gateway 只会持续降级；同时 server stdout/stderr 没有落盘。
4. 一次可恢复 ASR 错误会永久留在页面，即使后续字幕已经恢复。
5. Ollama 的实际 malloc/physical footprint 随短请求近似线性增长；一小时内未形成系统压力，但尚未证明多小时安全。

## 已实施的最小修复

- 针对现场音响采集，请求关闭 `echoCancellation`、`noiseSuppression` 和 `autoGainControl`，并把浏览器实际采用的设置写入 manifest/event。
- MLX 无 final 的额外等待从 5 秒缩短为 1.5 秒；超时记为 `asr.empty`，不翻译空文本，也不显示为服务故障。
- `run-local.sh` 监督 MLX 进程：退出后最多自动重启 3 次；日志写入 `${TMPDIR}/sermon-live-caption-poc/mlx-audio.log`。
- 页面在下一个成功 `asr.final` 后清除可恢复 ASR 错误；持久化、连接或 pipeline 错误不会被误清除。
- 新增只读长测评分器，统计延迟分位数、可用率、失败原因、重复短输出、语言漂移、资源增长和最终文件哈希。

长测结束后加入通用的连续重复短结果保护：同一个不超过 3 个词、24 个字符的 ASR 结果连续出现时，从第 3 次起记录为 `asr.suppressed/repeated_short_result`，不进入翻译。它不硬编码 `The.`，一旦出现不同或较长结果就立即复位。把该规则回放到本轮事件流会抑制 202/227 个 `The.`，保留最初两次和非连续结果。

该保护随后通过真实 Chrome → 内置麦克风 → Qwen → Gateway → MiLMMT 回归。Session `20260904T084619.073Z-59d01096` 播放同一源的 45 秒开场音乐：15 个 ASR processing 中，前 2 个 `The.` 保留并翻译，后续 13 个全部记录为 `asr.suppressed/repeated_short_result`，翻译仅调用 2 次；零失败，三份哈希匹配，WebM/WAV 完整解码。机器结果见 [soak-e2e-suppression-regression-20260904.json](./soak-e2e-suppression-regression-20260904.json)。

## 尚未关闭的风险

- 60 分钟修复长测已经通过，但一次通过不能证明 MLX 永不退出；监督器的受控故障恢复证据仍是必要的第二道保护。
- Ollama 资源增长没有造成系统压力或延迟退化，但 8192 context runner 在多场连续使用下的上限仍未证明。当前不采用会打断字幕的周期重启；周日开场前应从干净的 POC 启动流程进入，并继续记录多小时数据。
- 通用重复短结果保护只处理明显连续重复，不能完成真正的 speech/music classification。若现场会把敬拜音乐也纳入录音，后续应独立评估轻量 speech VAD；不要把单一词写入黑名单。
