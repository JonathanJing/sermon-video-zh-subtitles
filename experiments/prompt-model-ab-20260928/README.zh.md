# 讲章 Layer 2 提示词与模型小样本 A/B（2026-09-28）

## 结论范围

这是 **zh-Hans 单组初译与独立复核的诊断试验**，不是正式 Layer 2 策略、人工批准、整篇质量或发布验收。没有修改生产 prompt、模型路由、policy、候选或收据。现行正式策略仍要求 Astra 初译、Sol 独立复核及来源绑定的冻结 v2 policy；仓库中的 `config/target-language-policies/zh-Hans.json` 只是待完成模板。

本次 8 条初译样本中，四组输出都通过 ID／coverage 结构检查，匿名机器裁判均未标记关键语义错误。改写提示词在同一 Astra `medium` 下没有稳定优势：机器忠实度评分一条提高、七条持平；口语评分一条提高、一条降低。Sol `medium` 使用改写提示词时，机器忠实度与改写版 Astra 持平、口语评分有两条提高，且该组的实测响应中位数与按标准未缓存费率估算的 token 费用较低。Sol `low` 更快、更省，但有一条样本的机器忠实度低于 Sol `medium`。

独立复核的第二轮试验在 5 条译稿中各植入一个已知错误，另有一条干净对照。Sol `medium` 和 `low` 都修正了 5 个错误，并让干净对照通过；两个设置的六条输出均报告 `pass`，且结构、coverage、检查字段、空问题列表均通过核验。这个结果不足以证明 `low` 在真实整篇复核中与 `medium` 等效。

## 试验设计

- 输入：`experiments/mobile-live-translation/runtime-samples.jsonl` 的第 1、2、3、4、5、6、7、11 条。标签覆盖否定、经文类似引文、章节范围、专名、条件残句及较长讲章片段。每条独立构成一个 `zh-Hans` source unit；相邻语境为空。输入、模板策略、输出字段和 JSON mode 对四组相同。
- A：执行器现有初译指令，`gpt-6-astra`、`medium`。
- B：明确上下文仅用于消歧、保留残句及经文边界的改写指令，`gpt-6-astra`、`medium`。A 对 B 只改变提示词。
- C：B 的提示词，`gpt-6-sol`、`medium`。B 对 C 只改变模型。
- D：B 的提示词，`gpt-6-sol`、`low`。C 对 D 只改变推理强度。
- 每条样本的四组调用顺序按固定种子打乱。每条结果经一个匿名顺序打乱的 Astra `low` 机器裁判评分：忠实度和口语表达各为 0–4，另标记关键错误。裁判不知道组名；这不是人工盲审。没有做多次采样或第二裁判一致性检验。
- 第二轮在 A 组草稿上植入：不再蒙羞的反向目的、`4:4–7` 的错误数字、尼禄句的否定丢失、未完条件的擅自补全，以及紫色等级政策的反向否定；第 1 条作干净对照。复核提示词和输入保持一致，只比较 Sol `medium` 与 `low`，调用顺序打乱。

## 可复核证据与限制

原始响应、请求身份哈希、匿名标签映射、usage、单条机器评分和逐条复核证据保存在被 Git 忽略的 `artifacts/prompt-model-ab-20260928/`；该目录中的 `manifest.json`、`summary.json` 和 `reviewer-summary.json` 是汇总入口，`run_ab.py`、`run_reviewer_ab.py` 为本次执行脚本。它们没有提交到 Git，以免把模型原文和运行产物混入仓库。请求在发出前写 `started`，收到后持久化响应；不自动重试状态不明的付费请求。

样本只有中文，且使用诊断数据和未就绪的模板 policy，没有来源绑定的正式 v2 policy、相邻语境、语言插件、完整 Astra→Sol 候选准入链、人工审译或音频。匿名裁判也是模型；平均分差距为一条样本的量级，不能作显著性或非劣效结论。单条结果中，改写版 Astra 对较长的“紫色等级”片段出现更重复的口语表达；Sol `low` 对“不再蒙羞”的措辞比 Sol `medium` 略偏离英文。复核植入错误是明确、人工构造的，尚未覆盖隐蔽的神学、引文归属或跨单元遗漏。

## 下一决策

保留当前正式 Astra→Sol `medium` 策略和人审门槛。下一轮若要评估变更，应从已获授权、来源冻结的中／韩／西真实组各抽取代表样本，分别做同提示词的模型对照和同模型的提示词对照；加入真实 Sol 复核、语言插件、候选准入与匿名人工审译。重点比较关键语义错误、误放行、完整任务耗时和每个合格候选的费用。任何模型或提示词更换都应冻结新的 policy/version 与输出目录，不能复用旧模型证据或批准收据。
