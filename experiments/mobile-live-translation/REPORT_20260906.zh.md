# 手机媒体回路与 DGX / MacBook 运行时实验

日期：2026-09-06。范围为 [手机方案](PLAN.zh.md) 的 M0 媒体基线与 M1 运行时诊断；仅使用 MacBook Pro 和 DGX Spark，没有云 GPU。已完成两端 MT、桌面媒体与 Mac TTS 诊断；尚未取得真实手机、耳机声学或现场验收。

## 当前运行时结果

**现有 MacBook MLX Q5 配置更早返回完整译文；DGX BF16 更早出现首个中文。** 这两项不是同一个目标。语音分支需要有可提交的完整翻译单元，首个中文不能直接代表可起声时刻。

同一 v4.1 来源、冻结的 12 条开发输入，各端 2 次预热与 36 次正式调用。每条先取 3 次中位数，再汇总短句/自然长段各 6 条；p95 为线性插值。单位秒，`p50 / p95`：

| 当前配置 | 短句首中文 | 短句完整 EOS | 自然长段首中文 | 自然长段完整 EOS |
|---|---:|---:|---:|---:|
| MacBook Pro M1 Max，MLX Q5 | 0.335 / 0.367 | 0.484 / 0.582 | 0.517 / 0.563 | 2.253 / 2.809 |
| DGX Spark GB10，PyTorch BF16 | 0.050 / 0.051 | 0.614 / 0.821 | 0.061 / 0.063 | 6.731 / 8.572 |

两端最终正式运行均 **36/36 正常 EOS**，各 2 次预热另存。这是 12 个不同输入的性能与完整性诊断，不是 36 个独立样本的 SLA。输入、计时和模型冻结见 [运行时契约](RUNTIME_CONTRACT.zh.md)。

逐输入配对的 `DGX − Mac` 中位差：短句首中文 −286 ms、完整 EOS +130 ms；自然长段首中文 −456 ms、完整 EOS +4,478 ms。每端的 12 条输入在三轮内输出都稳定，跨端仅 2/12 的 token 与文本完全相同；其余差异保留，未据此评判译文质量。

Mac 当次只保存输入 token 数，没有保存输入 token IDs。之后使用相同 tokenizer 离线重建的 12 条 IDs 与 DGX 本轮全部匹配；该项是事后重建证据，不能冒充 Mac 当次捕获。

- 计时含本次输入准备和生成结束同步，排除网络、排队、ASR、断句和 TTS。Mac 为原生 MLX 流式返回，DGX 为 HF CPU token callback 后前缀解码；首中文观测边界不同，不能据此断言纯硬件 prefill 优劣。
- 两端精度、框架、内核与输出可能不同，是可部署配置对照。没有同精度单变量硬件对照，也没有本轮人工质量胜负或“超过 Google”证据。
- Mac 模型加载约 1.744 秒、校验 1.521 秒；DGX 模型与 tokenizer 加载约 48.436 秒、校验 3.929 秒。文件缓存未控制，加载范围也有差异，不能叫严格冷启动对照。
- DGX 前两次尝试分别因只读 Triton 缓存、临时挂载 noexec 失败，均未生成 token，原失败请求和日志保留。第三次只调整独立容器临时缓存目录与挂载执行能力，模型、冻结输入和库版本未变；最终成功分母不包含前两次失败尝试。
- 两台机器原有服务保留。DGX 为非独占环境，有既存 ComfyUI、llama-server 与 CPU 工作负载；结果不代表空载机器极限。

## ASR / TTS 的当前边界

DGX 现有 ASR 缓存为 Qwen3-ASR 1.7B BF16，Mac 的既有路径为 0.6B 8-bit；本轮尚未做同源音频的新 ASR 双端测试。不能把 MT 表格当作整条翻译链的耗时。

DGX 已核查的 qwen-tts 0.1.1 入口在整句 codes 生成并解码后返回完整波形。`non_streaming_mode=False` 不等于音频增量输出。现有 Base / 研究声线 checkpoint 也不同于 Mac CustomVoice，不能把两者首音频数字包装成同模型硬件对照。

Mac 的 [TTS 诊断入口](runtime_tts_mac.py) 已运行 1 次预热与 9 次正式调用，进程退出 0。开始准备时既有 POC 有活动采音，因此暂停加载；随后复查活动数回到 0，执行入口再次确认空闲才开始。没有停止用户采音或播放测试声音。

使用已有 CustomVoice 1.7B 8-bit、Uncle_Fu preset、固定 seed 与 18/28/40 字三个句子。每句每模式一次，以下是实测范围，不是 p95/SLA：

| 模式 | 首个 CPU PCM | 全部生成完成 | 实耗 / 返回音频时长 |
|---|---:|---:|---:|
| batch，整句返回 | 4.04–8.43 秒 | 4.06–8.46 秒 | 0.84–0.91 |
| stream，0.48 秒配置 | 0.47–0.56 秒 | 7.76–18.98 秒 | 1.73–1.93 |
| stream，1.0 秒配置（实际 codec 块 0.96 秒） | 0.87–0.93 秒 | 5.01–12.45 秒 | 1.12–1.26 |

**首块快，但本轮两种流式配置的持续生成速度都比其音频播放更慢。** 相同负载持续输入时存在积压/断音风险，不能据约半秒首块宣称实时听译已成立。这里首 PCM 终点是物化、同步并复制到 CPU，尚未进入网络、浏览器或耳机。

另外，28 字句的 batch 返回 6.56 秒音频，0.48/1.0 两种流式返回仅 6.24/6.40 秒，分别少 7,680 / 3,840 个样本。独立审计将这两条记为**样本覆盖未通过，原因尚未解释**。库报告的 codec 数相同，但未保存实际 codec IDs，不能断言码序列相同或直接把时长差认定为同一声音被截断。

不能直接按原 runner 的 `qualifiedFormalCalls=9` 接受。这一字段只通过了有限的正常结束、有限值与 fallback 检查；[独立审计](artifacts/tts-20260906/mac/audited-summary.json) 明确 **6 条流式调用均未通过持续实时接受**。上表的时间比值保留原始返回长度，两条覆盖异常的合格 RTF 置空；其余样本数一致也不证明语义或听感完整。

6 条流式调用均有 final 标记，未触发整块结束后返回全量波形的 fallback；但本次 codec 计数都未覆盖那个整块结束分支，不能排除源码已确认的风险。原始逐块 PCM、WAV、样本数、到达时间及 hash 全部保留，未去重或修补安装包。

见 [原始调用](artifacts/tts-20260906/mac/results.jsonl)、[原 runner 摘要](artifacts/tts-20260906/mac/summary.json)、[模型身份](artifacts/tts-20260906/mac/identity.json)。没有新增人工听感或语义质量验收。

## 媒体测试状态

独立 [探针及操作说明](media-probe/README.zh.md) 使用 16 kHz PCM16 mono、100 ms 帧和 WebSocket，验证网络回传与 AudioWorklet 播放处理；不含模型、WebRTC/Opus 或 SFU。

同一个 Mac 上的 Codex In-app Browser 顺序执行两轮 30 秒静音回路，使用相同 [v2 代码清单](artifacts/media-20260906/code-v2-manifest.json)。下表单位毫秒，`p50 / p95`；这里 p95 使用单轮帧测量的 nearest-rank，不能当跨设备或跨时段 SLA。

| 实际路由 | 控制 RTT | 收帧回执 RTT | 播放处理回执 RTT | 服务端收帧 / 播放处理回执 |
|---|---:|---:|---:|---:|
| 桌面 → Mac loopback → 同一桌面 | 0.60 / 1.20 | 1.30 / 1.80 | 102.15 / 104.70 | 299 / 299 |
| 桌面 → LAN 上的 SSH 转发 → DGX → 同一桌面 | 5.85 / 65.40 | 12.80 / 86.30 | 115.20 / 182.90 | 299 / 298 |

两轮都正常达到 30 秒时限，记录的 seq gap、网络/播放队列丢弃和 underrun 均为 0。DGX 一帧尚无播放回执就遇到硬停止；停止会清队列，因此不能说它完成了全部接收帧的播放。Mac 最后一条播放计时 observation 也未赶上服务器关闭该轮；统计按实际计数保留，未补造尾部数据。`played` 仅指该帧开始进入 Worklet 输出处理，不能证明整帧播完或耳机发声。

这些数据说明此处本机与 LAN/SSH 路径可工作，不代表“手机经公网直达 DGX”。每轮均为全零 PCM，既没有真实麦克风也没有可听声音；它们不形成手机或听感验收。计时从已成帧的 `emitPcm` 开始，未计首个麦克风样本等待 100 ms 成帧、模型、网络前的采音处理或实际耳机声学延迟。

- [Mac 30 秒摘要](artifacts/media-20260906/mac-v2/957e0716bd55bc5a.json)、[路由回执](artifacts/media-20260906/mac-v2/957e0716bd55bc5a.environment.json)。
- [DGX 30 秒摘要](artifacts/media-20260906/dgx-v2/3b2a06b36ed1f447.json)、[路由回执](artifacts/media-20260906/dgx-v2/3b2a06b36ed1f447.environment.json)。DGX 临时服务及 SSH 转发已在取回摘要后停止，未停止其他进程。

### 公网 HTTPS/WSS

最终 v3 进一步限制控制消息发送缓存为 64 KiB；8 秒没有 pong 或没有完成鉴权时，本地停采/清队列/断开。使用 [v3 快照](artifacts/media-20260906/code-v3-manifest.json) 在同一桌面浏览器通过 ngrok HTTPS/WSS 跑满 30 秒：

| 路由 | 控制 RTT p50 / p95 | 收帧回执 RTT p50 / p95 | 播放处理回执 RTT p50 / p95 |
|---|---:|---:|---:|
| 桌面 → ngrok 公网入口 → Mac 探针 → 同一桌面 | 33.0 / 116.9 ms | 84.6 / 155.7 ms | 240.0 / 323.6 ms |

收到 299 帧，297 帧有播放处理回执后到达硬停止；无 seq gap、队列丢弃或 underrun。两帧尚无播放回执，不能称完整声音播放。见 [摘要](artifacts/media-20260906/mac-v3/39c2aaf2bdcaadc6.json) 与 [路由/代码回执](artifacts/media-20260906/mac-v3/39c2aaf2bdcaadc6.environment.json)。这次也是静音 PCM，不是手机或声学结果。

该入口仅是 M0 临时 HTTPS 探针，未部署 Firebase admin/user，也未改变现有 Hosting 站点；ngrok traffic inspection 关闭，只转发独立探针端口。访问需要高熵短期 token，token 文件权限 0600；音频不落盘，token 不进入日志或摘要。服务于约 2026-09-06 10:11 PDT 自动到期，二维码在本地忽略目录单独交付；到期需启动新会话，不能把此日期报告当作持续服务状态。
