# 同行：现场声音定位使用说明

这项试用功能用于本期《耶稣与你同在》的同一份英文录制。原视频须以正常 1 倍速连续播放；证道范围为 29:53–1:07:13。它通过当前设备内的声音指纹匹配，将中文配音定位到现场正在播放的位置。

1. 打开本期正式播放版，点击“现场声音定位”。让设备听到正在播放的英文原声，尽量避开身旁交谈；使用支持麦克风的 HTTPS 页面。
2. 点击“听取后自动对齐播放”并允许麦克风，听取约 10 秒。中文配音会暂停；采集结束后自动停止麦克风，在设备内匹配。声音不上传、不保存。
3. 可靠命中后自动补偿等待时间、对齐并开始播放，播放开始后窗口自动关闭。若浏览器拦截或播放失败，点击“一键跟上播放”；系统按点击时刻重新计算位置。若结果过期，重新听取。若仍略有偏差，使用原有微调；外部视频已暂停或跳转时请重新采集。

随时取消即可停止本次定位。切页、锁屏或音频中断后，请重新开始；不要继续使用旧结果。浏览器若未自动开始播放，优先点击定位窗口内的“一键跟上播放”，以保留当前原声位置的等待时间补偿。

已经完成代码与取消清理测试、同源及错源离线测试，并在浏览器中让真实 AudioWorklet 和 Worker 处理模拟麦克风流。独立的 24 个同源位置全部命中，指纹位置最大误差为 0.017 秒；另一篇英文证道的 20 段独立样本全部拒绝。浏览器回放中的完整处理链时间差约为 −0.218 秒，这与单独的指纹位置误差不同。

2026-09-12 用户在 iPhone / iPad Chrome 上复测 C3 后确认“可以正常工作”；这是当前设备与录制的功能反馈，尚无精确机型/系统版本、设备输入延迟或实际礼拜场地统计，不能据此声称所有 iOS 设备或现场准确率通过。不同发布链接若使用完全相同的原声片段，声音指纹无法区分链接身份；变速播放也不在当前支持范围内。

## 每周索引构建

在本机用 `experiments/sermon-dubbing-poc/build_fingerprint_index.mjs` 构建索引。必须提供 `--source`、`--source-sha`、`--track-sha`、`--page-id`、`--start`、`--end`、`--out`；脚本先核对原视频哈希，再提取获准范围，输出非播放特征 JSON，不保存 PCM，拒绝覆盖已有输出。`start/end` 是原视频秒数。

将生成文件以完整 SHA 的前16位命名，绑定到该页 `audioFingerprint`；索引只用于同一时钟、与证道窗口等长的同步中文音轨。新录制需独立生成并做回放与负例检查，不能复用旧源索引。发布仍走每周发行校验，功能验收不升级证道人工审核状态。

代码验证：运行网页 `*.test.mjs` 和 `test_fingerprint_release.py`。媒体回放结果与真实麦克风/现场验收分别记录。

## C3 启动兼容与失败处理

C2 在首个有效 PCM 块后立即开始严格检查时钟；构造“首帧为 0、次帧跳到真实上下文时钟”的回放可复现立即中断。WebKit [318601@main](https://commits.webkit.org/318601@main) 修复了相关初始化行为，但未直接读取用户设备内部帧日志，因此这一设备根因仍属有依据的推断。

C3 丢弃至少 150 毫秒连续稳定的启动音频，然后开始完整 10 秒查询。正式录音后的缺帧、空输入和声道形状异常依然拒绝，不跨中断拼接。瞬时输入或音频会话中断最多自动重新采集两次，各次先释放旧资源；启动限时与总任务限时继续有效。错误只显示限定诊断代码，不输出原生错误消息、设备 ID 或音频。

版本登记：线上 C3 为 `rel_32ba9bea965c0bea90c14df5`。初次 Git 提交保留当时五个声音定位运行模块及其测试；本次自动流程更新 UI 控制器，保持四个 C3 采集/匹配模块不变。网页入口适配到 main 已有播放器。后续功能集成补齐页面、反馈和每周发行代码，并保留上述采集、匹配与自动播放实现；Git 合并与线上发行记录分别核验。

## 自动跟上播放

开始按钮已明确说明“听取后自动对齐播放”。可靠命中后，按采集末端锚点加上已流逝时间跳转，立即尝试播放；原生播放 Promise 成功后才关闭窗口。播放开始时核对当前位置，如缓冲造成超过 350 毫秒的差距，仅再纠正一次，不进行持续跟踪。宿主播放器的撤销起点在重试和纠偏时保留；可随时暂停或微调。

iOS 可能拒绝异步识别后的有声播放，麦克风权限不代表配音播放权限。[WebKit 播放策略](https://webkit.org/blog/6784/new-video-policies-for-ios/)与[Chrome 播放策略](https://developer.chrome.com/blog/autoplay)要求处理播放被拒的结果。此时窗口保留“一键跟上播放”，点击中同步重新计算位置、跳转和开始播放。定位锚自采样结束起有效 15 秒，单次播放连接最多等 8 秒；超过有效期重新听取。未就绪的音频保留尚未过期的锚供重试。

取消、切页、手动播放或跳转会终止未完成的自动操作；旧请求的迟到结果不得影响新操作。正式录音与指纹匹配仍使用已验收 C3 模块。自动流程已通过确定性测试、独立竞态回归及本机模拟麦克风下的真实 Worklet/Worker/MP3 播放；拦截恢复用明确模拟的权限失败验证。此前 C3 用户实机确认不代表新自动播放流程已在 iPhone/iPad 实测；单次纠偏也不能保证硬件或场地同步。
