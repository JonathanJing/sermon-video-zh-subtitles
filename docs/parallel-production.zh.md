# 生产并发与 MacBook 模型调度

已接入的并发保持相同来源、冻结文本和审核边界，不同时推进互相依赖的步骤。

| 分支 | 调度与汇合点 |
|---|---|
| 分块云端 ASR | 默认 2 个请求；按原顺序合并，保留成功块缓存。整文件单请求模式不拆分。 |
| 翻译批次 | 保留既有受限并发及有序合并。 |
| 原声指纹预计算 | 启用后与 ASR 重叠，缓存绑定来源 SHA、批准窗口、算法和脚本。最终中文音轨完成后另行绑定。 |
| 双 PDF | 阅读 PDF 与大纲分支默认 2 个任务；大纲完成后渲染同行 PDF，汇合检查 QA。 |
| PDF 与配音 | 配置 bridge 后，阅读稿及大纲就绪且配音前置条件通过时创建 v2 候选；PDF 与配音可重叠。缺少声音配置等准备条件记为等待；无效证据或实际运行错误仍失败。 |
| 原声对齐与 TTS | 两分支同时启动；合成组装完成后做 ASR 筛查，最终等待原声对齐再检查时序。 |
| 同视频审核 PDF | 两份 PDF 可并行渲染；人工听审仍单独保存。 |

冻结英文 → MFA → 中文阅读稿仍顺序执行。MFA 是上游 CPU 阶段；配音执行器的本地模型槽控制 TTS、原声对齐和 ASR 子进程，不是全系统模型服务管理器。发布、来源租约及最终审核仍由单一所有者顺序执行。

## 配置

- `--asr-workers 2`（1–8）：分块转写。
- `--pdf-workers 2`（1–2）：双 PDF 分支。
- `SERMON_LOCAL_MODEL_SLOTS=2`：配音本地模型并发槽，最多 2；未配置时，检测到至少 48GiB 总内存默认 2，否则 1。
- `SERMON_LOCAL_MODEL_RESERVE_GIB=12`：启动时可用内存门槛。可用量按 macOS free + inactive + speculative 页估算；不是硬内存预留，也不保证加载后的余量。
- `SERMON_FINGERPRINT_PRECOMPUTE=1`：启用原声预计算。最终绑定命令见[配音与 PDF 合同](parallel-dubbing-contract.zh.md)。
- `SERMON_DUBBING_CONFIG` 或生产命令 `--dubbing-config`：明确指定 bridge 配置。Saturday harness 会传递现有 `--bridge-config`。
- 配音执行器 `--serial-stages`：用于诊断的串行模式。

资源不足排队，等待取消或超时不会自动分发 Spark；既有可判定的运行环境故障才按 MacBook → Spark 策略回退。每条分支保留独立阶段收据和缓存；失败停止相关子进程，等待清理完成才释放任务锁。已生成的大纲只在输入、模型命令、生成器、术语和输出哈希全部匹配时复用。

## 实测与限制

[实验及复现说明](../experiments/local-model-concurrency-poc/README.zh.md)记录了 64GB MacBook 上同时加载 MPS TTS 与 MLX ASR 的真实短样本：推理调用区间重叠约 **1.69 秒**，采样最低可用内存约 **15.38GiB**。模型任务已结束并释放资源；生产按需启动，不常驻两个服务。

短样本并行墙钟耗时 16.45 秒，对照串行 25.28 秒，但模型加载缓存会影响比较，不能将其当作整篇提速比例。该实验不证明 GPU 内核同时执行、整篇音质或真实现场验收。完整周次还需实际运行、听审与发行检查。
