# L2 有上限的自动修复循环：复盘与设计

状态：设计。尚未实现。本页不改变任何门限，也不把自动修复后的结果称为人工批准。

## 一、复盘：过去的修复是怎么发生的

数据来自 [10-04 正式生产复盘](reports/20261004-full-production-retrospective.zh.md)、[10-04 生产日志复盘](reports/20261004-production-log-retrospective.zh.md)、[10-05 周日分层返工分析](reports/20261005-sunday-layer-rework-analysis.zh.md)和 10-08 的 605 端到端测试。

| 类型 | 实际情况 | 规模与成本 | 对自动修复的启示 |
|---|---|---|---|
| 真实语义错误 | 韩语 3 组、西语 1 组（各 474 组）术语、转折、数字上下文错误 | 韩语 6 次调用、西语 2 次，其余 942／946 个结果复用 | 少见，单组修复便宜。**这是自动修复最适合的场景** |
| 规则没有送到模型 | 中文引文映射只写在插件里，模型收不到；韩文模型自行加了编辑式经文编号 | 各语言全批重新译审 948 次，两轮合计 6,473,094 token | 这是系统性问题。逐组自动修会浪费且修不对，**应该在开跑前冻结规则，循环发现系统性失败要立即停** |
| 插件误拒 | 中文旧插件拒 20 → 新 0；韩语 4 → 2（剩下 2 个是真实错误）；西语 2 处 Sol 已通过的拼写数字被插件拒绝后改写 | 插件迁移 0 次新调用；西语那次改写浪费 4 次调用、13,610 token | **插件拒绝不等于译文错误**。Sol 已通过时，不应自动改写译文 |
| 前轮未完成的补跑 | 前轮提前失败，大部分组没有结果 | 1,730 次、4,298,792 token | 这是续跑，不是修复。循环必须区分"没有结果"和"结果失败" |
| L3→L2 时长修订 | 实测音频超时，改口播文字（中／韩／西 198／94／31 组） | 定向修订，复用生效 | 来源是 L3，不属于本循环 |
| 网络错误后重发 | 16 次 URLError，无用量记录 | 失败是否计费未知 | 未知结果先对账，不盲目重发 |
| 10-08 端到端测试，第 21 组 | 组内有典故 0-u076（"filled in the middle of a trial"），Sol 判 `completeMeaning` 与 `quotationAttribution` 不通过 | 链路在第 21 组停下，后面的组没有运行 | 引文归属问题多来自源文裁定，而不是译者措辞。**自动修只能试一次，不行就交给源文复核** |

另一个现象：现在的 runner 遇到第一个 Sol 不通过的组就整体报错（`run_target_language_models.py:1105`）。10-08 的测试因此只跑了 21／46 组，后面的组没有结果，判断不了失败是孤立的还是系统性的。

## 二、原则

1. **只自动修可局部修复的内容失败**。其他情况一律停下，交给人工、源文复核或工程。
2. **先判断是否系统性，再逐组修**。
3. **上限按英文单元链计算**，不因输出目录、组名、修订号变化而清零。
4. **未知结果不重发**，先对账。
5. **不改变批准语义**。自动修复通过的组仍是机器候选，人工审核照旧。机器写的只是给翻译模型的修复说明，不是裁定。

## 三、流程

### 1. 跑完所有组，再统一处理

runner 新增"收集失败"模式：Sol 不通过时保存证据、记为失败，继续其他组，不立即抛错。全部组跑完后得到一份失败清单。没有结果的组（执行失败、未知）单独列出，不算内容失败。

### 2. 确定性分类

| 来源 | 条件 | 失败码 | 动作 |
|---|---|---|---|
| Sol | `completeMeaning` 不通过 | `meaning_omission` | 修复 |
| Sol | `noAddedMeaning` 不通过 | `meaning_addition` | 修复 |
| Sol | `negationsNumbersNames` 不通过 | 按 Sol 的 issue 选 `negation_error`、`number_error` 或 `name_error`；判断不出 | 修复；判断不出则请求人工 |
| Sol | `quotationAttribution` 不通过 | `quotation_attribution_error` | **最多修复 1 次**，再失败转源文复核 |
| Sol | `uncertainty` 非空 | `evidence_insufficient` | 请求人工 |
| 插件 | Sol 通过但插件拒绝 | `language_plugin_failed` | 先重放插件（0 次调用），仍拒绝则交给工程，**不改写译文** |
| 执行 | 调用失败、返回无效 | `review_execution_failed` | 重试复核，计入上限 |
| 执行 | 结果未知 | `review_outcome_unknown` | 对账，不重发 |

动作沿用 `scripts/sermon_repair_planning.py` 的 `route_failure` 路由。

### 3. 系统性判断（修复前）

同一语言的一轮里出现以下任一情况，就不修复，直接停下并给出 `systemic_rule_or_policy_issue`：

- 同一个失败码出现在 3 组或以上；
- 内容失败的组超过总组数的 2%（至少 3 组）。

依据：正式轮里真实的语义错误只有 1–3 组（474 组的 0.2%–0.6%）；规则问题则会影响整批。阈值放在 2% 和 3 组，是为了让孤立错误能进入自动修复，而让系统性问题停下。

### 4. 生成修复说明并只重跑失败组

对每个可修复的组，自动生成 `partial_repair_brief`（schema `sermon-target-language-partial-repair-brief-v1`）：

- `failedRole`、`failedCacheSha256`：指向 Sol 的缓存；
- `failureReason`：失败码和 Sol 的原文证据（截断到固定长度）；
- `instruction`：按失败码的模板，加上 Sol 证据和英文源句。标明这是机器写的修复说明。

然后用 `--partial-repair-brief` 和 `--reuse-from` 重跑：只为这些组发新的初译和独立复核，其他组复用缓存，之后重新走插件和候选准入。

### 5. 上限

| 项目 | 上限 | 依据 |
|---|---|---|
| 每条英文单元链的内容修订 | 初稿之后 2 次（引文归属类 1 次） | 沿用 `Limits.content_revisions`；引文问题来自源文 |
| 每次修订的复核执行重试 | 2 次 | 沿用 `Limits.review_attempts_per_revision` |
| 无进展 | 同一失败指纹再次出现即停 | 沿用 `prior_failure_fingerprints` |
| 每语言每轮的修复调用 | 不超过 max(4, 基础调用的 5%) | 474 组时约 47 次（正式轮实际只用了 2–6 次）；46 组时 5 次 |
| 每语言每轮的修复 token | 不超过本轮初跑 token 的 5% | 防止长句反复修订失控 |

### 6. 结束状态

- 全部通过：照常进入插件和候选准入，结果仍是机器候选，人工待审。
- 有任何停止：写停止收据，包括组、失败码、尝试次数、证据路径和下一步需要谁。其他语言继续，不受影响。

### 7. 持久化

修订计数按 `(locale, 英文源包哈希, 锚点哈希, 单元 ID)` 记账，沿用 `machine_repair_ledger.py` 的写法：独占创建、哈希链，不能因为换目录而从零开始。未知结果占用预算，直到对账。

## 四、接入位置

1. `scripts/run_target_language_models.py:1105`：增加"收集失败"模式，替代第一个失败就抛错。默认行为不变。
2. 新增 `scripts/layer2_bounded_repair.py`：读取失败清单 → 分类 → 系统性判断 → 生成修复说明 → 调用 runner 重跑 → 循环，直到通过或停止。规划复用 `sermon_repair_planning`，指纹和预算复用 `sermon_strict_repair_planner`。
3. `scripts/run_scripture_gated_round.py` 和正式的 canonical controller 调用这个循环，而不是直接调用 runner。

## 五、验收

离线（零调用）：

1. 单组内容失败，一次修订后通过；
2. 连续失败，到 2 次修订后停止；
3. 同一指纹再次出现，提前停止；
4. 3 组同一失败码，判为系统性，修复调用为 0；
5. Sol 通过但插件拒绝，交给工程，调用为 0，译文不变；
6. 引文归属失败，修一次后仍失败，转源文复核；
7. 结果未知，进入对账，不重发；
8. 计数在换目录、换组名后仍然延续。

实测：用 605 端到端重跑。预期第 21 组修一次（2 次调用），如果 Sol 仍判引文归属不通过，就停在源文复核，并给出 0-u076 的复核材料。其余组应全部跑完。

## 六、机器做什么，不做什么

- **做**：收集失败、分类、判断系统性、写修复说明、只重跑失败组、记账、写停止收据。
- **不做**：直接改译文；设置任何批准；因为插件拒绝而改写 Sol 已通过的译文；突破上限；重发未知结果。
