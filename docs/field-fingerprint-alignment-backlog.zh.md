# 现场麦克风与音频指纹对齐：优化与验收 Backlog

更新：2026-09-29（洛杉矶时间）。归属 [Dev 统一 Backlog](backlog.zh.md) 的 `DEV-FIELD-001`；本文的 `FIELD-01`—`FIELD-10` 是其专项子项，不新增另一套顶层排期。本文为待实施计划，新增子项均为 `pending`，不是实现、发布或现场通过声明。

## 1. 范围和核查基线

本项目的“声纹”应准确称为**音频指纹**：辨认同一份已批准英文录音中的位置，不识别说话者身份，也不通过“是同一位讲员”推断是同一篇或同一秒。当前主路径只支持同一录音正常 1 倍速重放；重新讲述、临场插话、变速或另一剪辑版本不能悄悄继承同步能力。独立实时 ASR 仍属于 `DEV-LIVE-001`。

代码核查基线：`dev@7a35d0b081fee84d4ee95b0d0d5f995a5aae016c`。此次没有重跑声学实验。可复用能力与实际缺口如下：

| 已核对入口 | 已有实现 | 本轮不能忽略的限制 |
|---|---|---|

## 2. 建议执行顺序

先交付 `FIELD-01` 诊断和 `FIELD-09` 冻结基线，再做 `FIELD-02` 资料预备、`FIELD-03` 连续采集及 `FIELD-04` 采集 profile；随后验证 `FIELD-05` 时钟与 `FIELD-06` 三语映射。`FIELD-07` 防误跳、`FIELD-08` 交互/资源清理贯穿各次实现。`FIELD-10` 是基线通过后的可选实验，不阻塞原远场修复完成。

### FIELD-01：失败分类、录音质量和可解释诊断

- [ ] 复用现有错误码与 matcher diagnostics，区分：权限/输入未启动、输入中断、声音过小、削波、有效特征不足、无共识、重复片段含糊、索引/来源不符、结果过期、定位/播放失败。不能只显示“没有匹配”。
- [ ] 本地显示区间化音量、削波比例、连续帧/有效窗口、特征数、支持 anchor、覆盖及 runner-up 差距；音量高不标作信噪比高，启发式 confidence 不显示为正确率百分比。噪声估计只能是带假设的代理指标。
- [ ] 逐阶段计时：索引准备、权限等待、输入启动、实际采集、匹配、seek、恢复播放、最终字幕/可听输出；同时记录整个用户操作及累计占麦时间，不把并发阶段相加。
- [ ] 默认仅会话内诊断；用户明确选择分享时才导出白名单摘要。只保留公开内容版本引用、粗粒度 route/profile、区间化质量及耗时，不记录 device ID、蓝牙名称、PCM、现场 landmark、逐字稿或说话者身份；不借匿名收听统计开关自动上传新增诊断。

验收：每类错误有注入测试；诊断失败不影响停止麦克风；出口白名单测试阻止敏感字段和原始异常文本泄漏。

### FIELD-02：礼拜前准备与离线 readiness

- [ ] 复用现有索引存储，在用户选篇/下载时准备当前已选内容的指纹、绑定、字幕和目标音轨，并完成 SHA/schema/来源/时间原点校验。预备资料不请求麦克风、不默认下载全部历史。
- [ ] 将“可播放”“可离线播放”“可离线自动对齐”分开显示；缺指纹时允许普通播放，提示先联网准备。坏缓存、旧索引、撤回能力只禁用相应自动对齐。
- [ ] Web 先校验/预热索引再请求采音，复用已验证且身份匹配的 Worker/索引，减少录完才发现资料不可用；切页、语言、源或哈希变更立即失效。优化不得绕过每次使用时的绑定核对。

验收：冷/热缓存、完全断网、索引缺失/损坏、目录刷新、语言切换分别留证；冷缓存失败不能让用户白录 10 秒；统计准备时间和峰值内存，不将 HTTP `force-cache` 宣称为已完成离线保证。

### FIELD-03：同一次连续采集的 10→15 秒与预算合同

- [ ] 先设计兼容的采集策略/能力版本：保留旧 `captureSeconds: 10` 客户端行为，明确新客户端的 checkpoint、最大时长、算法和 profile。同步检查 binding/schema、Web 9—11 秒校验、iOS 7—12 秒 guard、worklet/accumulator、UI 以及测试夹具；不能只改一个常量或伪造旧 metadata。
- [ ] 同一输入会话积累连续 PCM，10 秒快照可靠命中即结束；证据不足时继续至同次会话上限，按真实窗口匹配。10 秒检查期间不重启麦克风，不拼接两次互不连续的录音，不把重叠的 10/15 秒结果当成两份独立证据。
- [ ] 保留原顶层“单次占麦最多 15 秒”的限制，将输入启动、checkpoint 计算和现有自动重试纳入同一占麦预算；不足完整窗口时使用合规的真实时长或安全拒绝，不补静音、不隐形延长。首样本时刻、样本数及窗口连续性必须可核对。
- [ ] 明确权限/资料准备、占麦、匹配和播放恢复的独立预算及整次操作截止；以低配设备实测冻结总时限，不把原 iOS 20 秒或 Web 35 秒直接解释为 15 秒新策略已兼容。权限、route、索引故障不走“多听 5 秒”；取消/超时后晚到授权也立即释放输入。

验收：覆盖 10 秒命中、延长后命中、15 秒安全拒绝、启动慢、检查点计算慢、frame gap、取消与晚到回调；新旧协议交叉测试；失败/取消不改播放位置，所有重试都计入公开预算。

### FIELD-04：麦克风路由与原始/AGC profile 冻结 A/B

- [ ] 保留 Web `raw-v1` 与 iOS `.measurement` 基线；新增远场 profile 独立 A/B。Web 读取支持能力与 `getSettings()`，区分“请求 AGC”与“当前报告的设置”；缺字段记 unknown，不伪造 true。
- [ ] iOS Voice Processing 必须核对实际启用状态、输入/输出 route、采样率和 channel；不把 `.voiceChat` 这一字符串当作 AGC 已生效。目标 SDK API、最低系统可用性及实际处理组合须在开发时核验；处理不支持则回退，不扩大权限。
- [ ] 首轮只比较 raw 与 AGC profile；降噪、回声消除、滤波分别作为后续单变量实验。AGC 可能同时放大噪声；语音增强可能改变指纹特征，不能以“听起来更清晰”代替匹配证据。iOS 处理组合不能拆分时按整体 profile 比较，不将收益单独归因 AGC。
- [ ] 明确内置麦、耳机麦、有线/蓝牙等输入输出组合；提供“拿出手机、避免遮挡麦克风”的提示。不能假定听耳机时一定由手机麦克风采集，也不能假定浏览器允许独立指定输入输出。
- [ ] 基线仍在采音前暂停本机配音，避免收录自己的目标语言音轨；仅在隔离验证通过的耳机路线实验不中断收听。途中 route/格式/时钟变化取消本轮，不跨输入拼接 PCM。

验收：近/中/远同源条件下按平台及实际 profile 分层比较；报告设置、拒绝原因和耗时，不能把系统不支持的 profile 算作实验失败或成功。

### FIELD-05：采样时钟、处理/输出延迟与可听对齐

- [ ] iOS 研究使用 tap 提供的音频时钟/有效样本计数建立首样本与单调时钟的映射；验证 host/sample time 有效性和连续性。无法建立可信映射时记录退化模式或安全拒绝，不能把回调抵达时间当作物理录音起点。
- [ ] Web 复用现有 AudioWorklet 和 context/end time 校正，增加主线程卡顿、消息延迟、context suspend 与重采样测试；不是再次“迁移到 AudioWorklet”。若采用新的时间 API，先核对其输入/输出含义，不能把 AudioContext 输出时钟直接当成 HTMLMediaElement 的音频时钟。
- [ ] 为匹配结果明确 query 起点/终点与时钟域，补偿只做一次。概念公式为 `sourceNow = querySourceStart + elapsedSinceFirstSample`，且仅在同一录音持续 1 倍速前进的假设下成立；去掉预热样本或裁剪窗口时同步移动起点。
- [ ] 保留现有恢复播放后的二次校正和过期防护，分别测 index 位置误差、seek/缓冲耗时、实际可听输出误差与字幕 cue 高亮误差。有条件用已授权参考录音和受控回放测 route 延迟；不把固定蓝牙常数应用于所有设备，也不重复加算已被时钟覆盖的延迟。
- [ ] 冻结对齐参考是听众位置实际听到的现场声音，而非未校准的舞台时钟；不凭估计座位距离补传播延迟。无法观察现场播放器后续暂停/跳转时，不声称持续跟踪，提示重新点按。

验收：注入延迟、帧丢失、重采样、首尾边界及播放启动慢；在目标设备/路线记录误差分布和符号，不能仅检查传给 seek 的数值。

### FIELD-06：英文位置→三语音轨→字幕/阅读单元

- [ ] 将“指纹正确”和“目标语言定位正确”分开验收；冻结完整视频、source clip、index、目标音轨及字幕的零点。来源/语言/index/track/caption/map 哈希或版本任一变化都重新验证能力。
- [ ] 共用源时间轴的已审同步音轨按声明的零点转换；自然紧凑音轨或双稿内容仅使用已批准的 source-unit/anchor 映射。禁止按全文行号、字符比例或全片时长比推算另一语言的位置；映射缺失只禁用自动跳转，不伪造内容。
- [ ] 分别验证中文/韩语/西语在首、中、末段、重复经文、一对多/多对一、留白、缺失单元及源窗口外的行为。源处于真实留白时保留留白，不能为了显示一句字幕擅自跳到下一句。
- [ ] 定位结果携带同一来源和播放 revision，由唯一播放器提交；时间按钮、当前 cue、全文跟随和系统媒体状态使用同一提交结果。用户正在手动阅读时不强制滚屏，保留“回到当前句”。

依赖：复用 `DEV-IOS-001` 的跨轨 source-unit/历史合同及 Layer 4 发布绑定，不在现场修复上游翻译、TTS、句界或审核状态。验收须同时包含源位置正确、当前音轨位置正确、字幕单元正确三个断言。

### FIELD-07：重复片段、质量门槛与误跳防护

- [ ] 先冻结并复用现有 votes、独立 anchor、覆盖、runner-up、match fraction 和三段覆盖门槛。新采集策略不得下调阈值；换算法/加权规则另开版本，用独立保留集重新验证。
- [ ] 增加公共片头、相同音频插入两次、重复播放经文、音乐、掌声、附近谈话、别篇及本机配音负例；“不是噪声”不代表“来自正确源”。对不可唯一定位的片段继续收集证据或拒绝，而不是选择分数略高的候选。
- [ ] 实验跨窗口时间一致性时，仅把新增长的非重复 anchors 作为额外证据；比较 offset 增量与真实采样间隔，冲突即拒绝/过期。当前播放位置只能作可丢弃的搜索先验，不能掩盖另一处强候选或强迫匹配；手动移动或源跳转后失效。
- [ ] 对有效匹配但超出预先冻结“大跳转”范围的操作，试验展示目标时间/片段后确认；确认时重新核对时效并补偿等待，不重复使用已过期结果。该交互不能让低置信候选绕过自动匹配门槛。

验收：一条 false positive 单独记录并阻止该候选策略推广；不要用更高命中率抵消误跳。重复 checkpoint 不能累计成虚假的统计样本。

### FIELD-08：可恢复交互、手动微调与隐私生命周期

- [ ] 状态明确区分准备资料、等待权限、输入启动、听取中、证据不足继续听、本机匹配、定位中、已对齐/失败；已有错误码扩展为可操作提示，不要求用户理解声学参数。
- [ ] 继续提供取消、重试、手动 ±0.25/±1/±5 秒和撤销；保留原播放/暂停意图，用户新操作优先，旧回调不覆盖。自动偏移和手动偏移分离，绑定 page/source/locale/track/map 身份，route 或源变化后不盲目复用。
- [ ] 麦克风权限只在明确点按后请求；不持续监听、不后台重开、不自动循环重试。结束、切后台、锁屏、来电、切页/轨、撤回能力、超时及晚到授权均验证停止输入并清理内存引用；不能承诺托管运行时的内存被取证级安全擦除。
- [ ] 已对齐只代表本次定位；显示必要的新鲜度，用户发现现场暂停/跳转后可再次点按。没有采音时不能声称检测到了现场漂移，更不能按墙钟持续自动跳转。

验收：同一回归脚本覆盖失败不跳转、取消不晚跳、暂停不意外播放、撤销可用、输入实际停止；VoiceOver、多语言、窄屏与大字下取消/微调按钮始终可达。

### FIELD-09：真实声学基准、跨端 parity 与发布门禁

2026-09-30 首批代码状态 **in_progress**：现有 JS→Swift golden 生成器新增不重写 fixture 的检查与 hash 绑定报告，12 个合成场景和独立本地 Swift matcher 对照通过。见 [冻结数值合同检查](field-fingerprint-contract-baseline.zh.md)。仅覆盖 published 数值合同，以下声学、legacy packed、设备和现场验收继续待证据。

- [ ] 复用 [JS→Swift golden 生成器](../apps/tongxing-ios/scripts/generate-published-fingerprint-golden.mjs) 做确定性数值和拒绝原因对照；记录算法/索引版本，覆盖旧 packed 与 published 的隔离。合成音只证明合同，不代替语音/现场。
- [ ] 使用经授权的录音/受控房间回放，分开生成开发集与保留集，按完整源录音/录制会话分割，避免把同段重叠窗口随机分入两组。包含不同证道、不同起点、转码、音量、EQ、混响、邻近人声、手机遮挡与网络状态；改剪辑/变速仍为不支持或负例。
- [ ] Web Safari 与原生 iOS 分开，最低支持设备/系统与当前设备/系统、内置/已支持耳机路线分层；正例失败、拒绝和超时全部保留。报告成功率、误跳率、首次/二次命中、P50/P95 总耗时、源定位/可听输出/字幕误差、峰值内存及占麦时间。
- [ ] 保留原 P0 小规模门槛：远处同源至少 10 次中 9 次正确、至少 30 次负例零误跳；不得解释为已证明真实误跳概率为零。扩围建议：每个平台至少 100 次独立正例和 300 次负例，覆盖至少 3 个不同源及 2 类设备，列出每个 route/噪声分层的样本数和置信区间；不足者明确限制推广范围。
- [ ] 新增候选精度目标（待基线后、试验前冻结）：已接受正例的源定位绝对误差 P95 ≤0.5 秒，可听输出相对听众现场参考 P95 ≤1 秒，并单独核对正确字幕单元。拒绝/失败仍计入成功率分母，不能只留容易样本。总时间/CPU/内存预算由基线冻结后再验收，不预报提升百分比。
- [ ] 先本地 shadow 只展示诊断/候选、不自动 seek，再 Dev 受控自动定位，最后小范围真机/会场 A/B；新 profile 可回退旧实现。新增 Web 模块同步 build/deploy allowlist、同源策略、哈希和离线缓存；代码 CI、Dev HTTP、设备和现场分别留证。

### FIELD-10：非阻塞后续实验，不作为本轮默认方案
