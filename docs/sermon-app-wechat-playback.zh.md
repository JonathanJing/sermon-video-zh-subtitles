# 微信扫码后音频加载阻塞修复

2026-09-05，用户在 iPhone 微信扫码后可看到标题与字幕，但播放器停在“正在加载音频”，播放按钮禁用。

## 已确认与仍待确认

旧前端在选中音轨时禁用全部播放与定位按钮，仅在 `loadedmetadata` 后启用；点击播放处理器也直接拒绝禁用状态。浏览器若推迟音频预加载，用户无法提供启动播放的点击，形成等待闭环。音频 `error` 后同样禁用按钮，缺少重试。

本机在线请求确认 MP3 返回 `audio/mpeg`，首部与尾部分段请求返回 HTTP 206。这仅证明本机到服务器的路径正常，不证明用户手机网络正常，也未直接采集手机微信内部事件。WebKit 建议音频启动依赖用户点击并处理播放拒绝；不能据此断言所有微信或 iOS 版本都拒绝预加载。参考：[WebKit 播放策略与开发者建议](https://webkit.org/blog/7734/auto-play-policy-changes-for-macos/)。

## 修改

- 音轨存在即可点击主播放键与弹窗播放键；时间定位仍等待有效元数据。
- 保留原生 `play()` 在用户点击内同步调用，错误后可直接重新加载与重试。
- 启动等待可再次点击取消，15 秒未完成则显示重试及浏览器/MP3 备用提示。
- 提前显示来源与音频哈希匹配的书签；用户点击继续后，元数据到达时重新校验并恢复位置。读取元数据本身不自动播放。
- 换音轨、取消、旧播放 Promise 拒绝及旧来源 metadata 不应覆盖当前状态。

发布目录：`artifacts/sermon-dubbing/2026-09-05-weekly-app-v13-wechat-startup/`，appVersion `e954aa579755d44f`。仅更改发布的 `app.mjs` 与 `engagement.json` 中的版本值；29 个文件中的周次内容、音频、品牌资产、反馈目录保持不变。
