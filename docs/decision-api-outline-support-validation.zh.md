# 大纲来源支持：下一轮质量与人审收益验证

日期：2026-10-06。状态：design_ready；本轮只完成方案，不发起新API请求，不修改生产合同。此前在线结果见[第三轮报告](reports/20261006-decision-api-semantic-classification-results.zh.md)。[机器计划](../config/decision-api-outline-support-validation-plan-v1.json)为设计草案，现有producer／runner不消费它。

后续用户选择先做机器可行性。已完成[四新来源／24项机器子阶段](reports/20261006-decision-api-outline-feasibility-results.zh.md)，不等于本文48项人审A/B已执行；后续新留出需排除该四源及前六源。

## 目标与现状

验证两个问题：Decisions能否识别“引用合法但意思不受来源支持”的大纲问题；其提示能否在不降低最终审核质量的前提下减少人工核对与修订时间。

此前六篇／36条实际大纲中，Decisions全判支持，与新增Sol分类一致35/36。这些主要是正常草稿，缺真实严重错误及独立人工gold；Sol不是当前人工审核基线。现行[生成器](../scripts/sermon_study_generation.py)只检查结构和引用，内容审核仍由[study review](../scripts/study_artifacts.py)及[人工收据schema](../schemas/sermon-study-review-v1.schema.json)负责。下一轮不拿程序引用校验与Decisions比赛。

## 判断单位与来源范围

一项案例为一个完整大纲小节：标题、points、原引用IDs、相关英文来源与上下文。同一小节逐条标注主张span；保留完整原句、限定词和整句经文，不以自动改写的“原子主张”代替原文。中文来源只辅助阅读，英文为本轮来源对照；冻结[系列术语](series-terminology.zh.md)与该稿既有术语身份。来源本身有ASR／翻译疑点时单列，机器不能靠大纲反推来源。

程序先做两臂共同的身份hash、引用ID存在性、覆盖／文本格式检查。已知错hash、空材料、非法引用及已编码状态直接由程序处理，留在准备失败分母；不进入模型语义胜负面板。

每个主张问一个choice：
- supported：当前提供的来源支持全部限定、关系和归属，可为忠实意译。
- contradiction：当前来源明确否定／反转该主张，或明确显示引语属于另一说话人。
- unsupported：当前引用材料可理解，但不足以支撑新增断言／保证／归属；标签仅表示当前引用不支撑，不宣称整篇从未说过或主张本身为假。
- needs_more_evidence：来源有截断、缺上下文、歧义或缺可用英文，无法可靠区分支持、矛盾和新增断言。

多问题优先序：可明确成立的矛盾 > 可明确成立的当前引用不支持 > 尚缺证据 > 全部支持；无法区分时保留needs_more_evidence。同时保留逐主张标签，避免只用一个小节标签掩盖错误位置。

整小节另问framing：faithful／misleading／needs_more_evidence。大纲可以概括和省略细节；只在标题、重点或删去必要对照导致讲道论证改变时判misleading，不能要求大纲复述全文。

辅助定位可从已提供的sourceUnitIds中选择best_reference或no_sufficient_reference；它是“去哪核对”的候选，不是证据成立证明。程序校验ID并打开完整上下文，Decisions不生成解释、经文或修订稿。A也有相同来源目录、搜索与链接，B多出的仅为机器分类、候选定位和队列提示。

## 样本与来源级隔离

先用此前六个开发来源做rubric校准；它们和36条旧样本都不进入新的留出结论。新留出目标为六篇未用于此次开发的讲道，每篇八个不同底稿，合计48个完整小节：

| 每来源 | 合计 | 材料与用途 |
|---|---|---|
| 2项 | 12 | 未改写的真实生成大纲；独立标注，不能默认正确 |
| 1项 | 6 | 从真实来源做忠实意译／合理概括，检验误报 |
| 4项 | 24 | 引用ID仍合法的严重语义变体，检验漏检 |
| 1项 | 6 | 语义上缺必要上下文的来源窗口，检验弃权及补证据流程 |

每个底稿只输出一个形式，不能让审阅者见到该底稿的正确版和错误版。人为改写样本记录parent hash、修改span、family、作者预期，但这些字段不进入模型输入／计时审阅界面；作者预期不是gold。真实12项与36项人为变体分列，不能混合估计周流程真实错误率。

24个严重变体覆盖以下六类，每类目标4例并跨来源分布；每项只植入一个主要问题，语气与长度尽量自然：
1. 限定放大：可能→必然、部分→全部、特定条件→无条件。
2. 引语错归：质疑者、反例或被否定观点写成讲员教导。
3. 断章取义：遗漏紧邻的否定、例外或后续纠正。
4. 应用越界：故事描述变成普遍命令，盼望变成结果保证。
5. 关系反转：条件、因果、让步或责任对象改变。
6. 整体选择性遗漏：各句局部都能找到依据，但标题或删去关键对照使整段论证偏移。

库存与人审人员尚未核验／落实，不能宣称48项已备齐。若没有六个新来源或某类无法自然构造，记录缺口；不以复制旧来源或生硬错误凑数。批次上限按实际claim数／question数与完整来源大小预检，拆批不截断上下文。

## 独立标注与证据

Gold由独立人工在看不到任何模型输出和变体作者标签时建立；两人分别标注，分歧再裁定。保存claim span、当前窗口标签、全来源查证结论、严重度及具体source IDs／原文span。

必须区别“当前引用未支持”和“查完整来源后仍不支持”。若主张在其他段落成立，最终处置应补引用／补上下文，不把它当内容必须删除。来源窗口不足案例的gold需同时记录完整来源与删去的必要上下文，不能用缺证据标签掩盖可确认错误。

引用合法、两模型一致、Agent盲审或source traceability不充当human gold。未裁定项单列，不能进入已知真值准确率分母；预先定义的严重挑战如果未裁定，不把本轮作为完整质量门通过。

Gold审阅人员与计时审阅人员对同一来源不得重叠；变体作者也不能计时审其所写材料。理想为两名gold标注者及两名计时审阅者，实际可跨不同来源复用角色，但同来源隔离必须保持。人员不足时只做材料／机器可行性报告，不报告人审收益因果结论。

## 两个面板，分开回答能力与收益

### 面板一：机器质量

B在冻结来源窗口上做逐主张、整段framing与候选定位。与独立人工gold对照，记录严重错误未提示、错误误判supported、忠实改写误报、窗口不足识别和补证据后变化。部分已有错误标签／状态可由程序直接判定的项不当作额外语义能力。

先在旧开发来源上固定rubric、概率／弃权处理及队列策略，再跑新留出。API概率不是已校准正确率，本小轮不按任意“0.9即安全”自动通过。只有明确问题标签或有效补证据动作才算机器提示；一律needs_more_evidence不算检出严重错误。

若需要补上下文，共享来源导航最多扩展一次；两臂始终能访问同一完整来源，B的扩展时间与请求费用计入B。未解决问题保留，不能删除慢案例。

### 面板二：真实人审A/B

A：现有程序预检＋人工核对来源、修改大纲／引用、形成最终结论。
B：同样流程＋Decisions提示；机器supported仍需人工审核，不能自动批准。

两名计时审阅者审核相同48项；每个来源由一人用A、另一人用B，六来源均衡交换角色。任何人不跨臂审核同一来源，避免记忆和先看到提示的污染。每项最终交付相同：逐主张审核、必要修订／引用更新、整段论证结论与来源依据。两个版本在隔离实验空间保存，不写生产批准收据。

来源顺序和小节顺序随机化，A/B题目不显示是否真实、变体类型、作者严重度或gold。除机器提示外，界面、来源窗口、搜索、术语和交付要求一致。记录审阅者和来源效应；六来源的小样本只作探索。

## 指标与继续门

| 指标 | 计量口径 |
|---|---|
| 最终人审严重错误漏检 | 未定位并正确处理的预定义严重问题；A/B分别报，不能仅凭“需复核”算已检出 |
| 机器漏提示／误报／弃权 | 逐claim和整小节分别计；真实、变体、缺上下文分列 |
| humanActiveSeconds（主要时间指标） | 阅读、定位、核对提示、修订、引用修复、形成有效终点的人工active时间 |
| API／准备／calendar时间 | 模型调用、程序准备、等待与总wall独立记录，不把API速度当人审节省 |
| 返工／有效完成率 | 最终仍不受支持、错改忠实原文、需要再次审核、未解决或超时数量 |
| 增量费用 | Decisions全部初次、定位、扩展与稳定性调用；人工分钟另列，不虚构人力美元 |

计时前冻结active开始／停止按钮规则，等待／休息不计active但记录wall。达到8分钟观察上限仍未完成的项保留为未完成，计入completion与受限时间面板；不能剔除后只报快样本。报告每来源配对差、审阅者差、整体中位数／p95及来源级不确定性，不把同源小节当独立来源。严重漏检的阳性分母以最终gold为准，不把所有48项当严重错误。

本小轮的继续条件为：B最终人审未漏掉任何已裁定严重挑战；不新增严重错改；六条忠实改写中机器误报最多一条，真实草稿的误报另列；B有效完成数不低于A、人工返工项数不多于A；humanActive中位数改善目标至少20%，且逐来源／审阅者结果不显示由单一来源或人员造成。满足只允许进入更大新来源验证，不宣布生产胜负。若区间或来源数不能支持改善，则inconclusive。阈值在新留出执行前冻结，不看结果后修改。

24条严重挑战即使零漏检，在假设独立同分布时单侧95%召回下界仅约88.3%（0.05^(1/24)）；来源相关性更不能据此证明可靠替代人审。本轮不沿用“零错就安全”的判断。

若B最终人审漏掉一条已裁定严重错误，停止晋升，保留当前题目与所有结果做定位；可以完成隔离诊断，但不能用改题后的答案覆盖或混入同一轮。错源、伪造完成、人工gate绕过、预算超界或未知请求重发立即停止。下一版题目需新身份与新留出，不反复试到通过。

## 时间块、预算及执行顺序

| 阶段 | 观测／工作块 | 产物 |
|---|---|---|
| 材料准备与任务校准 | 45–60分钟 | 新来源清单、48项候选、source／draft／rubric hash；缺口清单 |
| 独立标注与裁定 | 每标注者90–120分钟起 | blinded gold、来源span与裁定记录；未完成则继续，不降低标准 |
| 机器面板 | 20分钟在线观测 | 原响应、receipt、逐claim质量及扩展记录 |
| 人审A/B | 每计时者60–90分钟起 | active／wait／wall事件、最终修订和来源依据 |
| 分析与报告 | 30–45分钟 | 分来源结果、错误案例、继续／停止结论 |

时间块是规划值，标注与人审耗时尚未测。人员安排、新来源和独立gold齐备，冻结本轮payload／随机表／交付格式后才进入在线质量与收益面板。

沿用总API授权$20；目前ledger累计估算$2.995649，余额$17.004351。本轮设计增量上限$2、最多120个Decisions请求；所有定位、扩展和重现调用都占同一个限额，不新增Sol对照调用。该额度为已有总授权内的研究分配，非新增授权或实际账单；执行前重新核对live ledger，唯一封存／承接第三轮，不重置预算。

只使用现有dev环境；请求前完整预留、无隐式重试，unknown对账前不重发。若当前预算不足或最大问题数／输入上界不允许完整材料，缩减有明确身份的新子阶段并记录，不截断来源或绕过guard。原机器收据、生产review schema和发布流程不变。

## 首次执行的交付与状态

1. 可复核的来源／样本manifest：原稿、真实来源上的变体和缺上下文项分开，包含hash及source-level split。
2. 隔离gold文件和逐源随机分派表：机器／计时人员无法读取作者标签或gold。
3. 机器receipt与人审事件：对每项记录是否完成、扩展、错改与返工；匹配身份才统计。
4. 报告只给shadow_candidate／revise_rubric／inconclusive／stop_promotion；不输出自动发布或human_approved。
5. 原始私人内容与人审身份保留ignored artifacts；Git仅保存方案、执行代码和安全聚合。

当前仅有设计，无新API请求，无新的48项gold、人工计时或生产接入。后续实现须使用新阶段runner，不能用当前“新增Sol分类对照”冒充本方案人工A。
