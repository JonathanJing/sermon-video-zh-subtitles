# 周更运行配置：并发、请求上限与预算预留

本页是正式周更和周六片段彩排的默认运行配置（2026-10-13 起）。数值来自两次真实运行的账本：

- 2026-10-11 周更全篇：461 句，三语。
- 2026-10-12/13 片段端到端：16 句，三语，dev API，账本在 `artifacts/clip-test-20261012`。

[本地生产 runbook](codex-local-production-runbook.zh.md) 按本页开工；需要偏离时记录理由。已冻结的 run 保留原配置，不原地改动。

## 结论先行

1. **瓶颈不在并发。** 10-11 周 12.5 小时里纯计算约 1.5 小时，其余是返工和等人（见[复盘](reports/20261011-weekly-release-resi-54475d42-retrospective.zh.md)）。片段测试同样如此：中途卡住的几次都来自预算预留用完、开工条件缺失和质检代码变更。并发再调高，节省的时间也只是分钟级。
2. **预算预留按最坏情况计，约为实际花费的 8 倍。** 每次请求都按请求上限预留，用掉的部分不退。上限给得不够，就会中途 `budget_exhausted` 或 `source_budget_exhausted`。片段测试因此停了三次：中文 Layer 2、西语校准、中英音频质检。
3. **Layer 2 的输出上限可以从 4096 降到 2048。** 实测 329 次 Sol 调用（10-11 周 220 次，片段 109 次），最大输出 623 tokens，p99 为 471。降到 2048 后，每次预留从约 0.058–0.063 美元降到约 0.038–0.043 美元，仍有 3 倍以上余量。超出上限的回复因 `finish_reason` 不是 `stop` 而判为不完整，该组按失败处理并走修复，不会放过截断的译文。

## 并发设置

| 环节 | 设置 | 说明 |
|---|---|---|
| Layer 2 翻译与复核（OpenAI API） | execution-v3 `layer2AutoRepair`：`groupWorkers: 8`；`maxActiveLocales`：正式周更 3，10 美元以内的 dev 测试 1 | 共享 job-root 的 API 槽位上限 24（[controller 合同](canonical-layer2-controller.zh.md#并发上限)）。三语同开时，三份预留同时占用预算 |
| 文本质检与校准（OpenAI API） | `run_machine_qc_clip_test.py --workers 8`；预算账本 `maxConcurrent` 16 | 只在 Mac 上调 API，不占 Spark，可以与另一语言的 Spark 环节重叠 |
| 配音渲染（Spark） | `--spark-production`：8 个常驻副本、每批 8 句、CUDA/BF16/SDPA | 全篇约 6–8 分钟／语言 |
| 静音压缩（Spark CPU） | 单任务 | 约 15 秒／片段 |
| 配音初筛 ASR（Spark） | `--batch-size 1` | 全篇约 3–4 分钟／语言。改用 batch 4/8 会改变 ASR 设置身份，需新校准，收益约 2 分钟／语言，暂不改 |
| 音频质检（Spark + API） | `--workers 4`，`--max-api-calls 150`；**与该语言的文本质检共用同一个预算授权（同一 `budgetRoot`）** | API 评判的回复缓存就是该授权的预算账本。换新的预算根会把文本校准的评判全部重买一遍：2026-10-13 实测每种语言多花约 0.3–0.38 美元、多 3.5–5 分钟（校准预取 211–288 秒，共用时 0.8 秒） |
| Spark 整体 | 独占会话内同一时间只有一个 GPU 任务 | 三种语言的渲染、初筛和音频质检依次进行 |

### 编排

1. 三语 Layer 2 同时开（正式周更）。
2. 每种语言的候选一出来，就在 Mac 上跑该语言的文本质检，不必等其他语言。
3. Spark 按语言依次做渲染 → 压缩 → 初筛 → 打包 → 音频质检。
4. 文本质检和 Layer 2 都只调 API，可以与另一语言的 Spark 环节重叠。

这样能省掉三语文本质检的串行时间，全篇约 10–20 分钟，但前提是所有开着的预算加起来仍在批准范围内。

## 预算预留怎么定

规则：**已结算花费 + 当前所有开着的预算上限 ≤ 批准总额**。上限按下表"预留"列设定，再留 20–30% 余量；一个预算结束后，只计它的实际结算。测试预算很小时，把花钱的环节一个接一个跑，每次只开一个预算。

每次请求的预留按上限算：Layer 2 每次约 0.038 美元（片段）/ 0.043 美元（全篇，2048 tokens）；质检每次约 0.011–0.0125 美元。

| 环节（每种语言） | 片段彩排 16 句：调用 / 预留 / 实际 | 全篇 461 句：调用 / 预留 / 实际 | 建议上限 |
|---|---|---|---|
| Layer 2（翻译＋复核，一次修订） | 约 32 / 1.2 / 0.22 美元 | 约 75 / 3.2 / 0.6 美元（10-11 周三语 220 次，实际 1.73 美元） | 片段 1.5；全篇 5（含一次修复修订） |
| 文本质检＋校准＋音频质检（同一预算根） | 约 210＋20–50 / 2.6 / 0.35–0.45 美元 | 约 1,450＋音频专有调用 / 约 20 / 约 2.5–3 美元 | 片段 3.5；全篇 30 |

片段彩排三语一轮实际约 2 美元（2026-10-13 分开预算根时为 2.69）；按上表依次开预算，最坏情况始终低于 10 美元。

## 开工条件（片段测试中实际卡住过）

- **开工前跑一次检查。** 用 `scripts/check_run_start.py`（PR #382）一次查完代码与质检实现哈希、凭据启动器、预算计划、Spark 主机和已部署代码、输出目录、测试页 ID；预算文件用 `scripts/plan_run_budgets.py` 按 `config/weekly-run-profile.json` 生成，不再手写。
- **只有 GPU 环节占用 Spark 会话**（PR #380 合并后）：Layer 2、文本质检等只调 API 的环节不检查会话、不建 job hold，Spark 服务照常运行；渲染、初筛、音频质检前才 `spark_exclusive_session.py begin`，用完 `finish`。合并前的代码里 Layer 2 仍要求会话（`spark_exclusive_session_required`）。
- **GPU 环节的会话出状况时**（job 异常退出后变成 `reconcile_required`）：先确认派发进程已退出、账本里没有 intent 状态的请求，再 `reconcile --job-id … --confirm-dispatcher-terminal`，最后 `resume-begin`。
- **QC 换预算根时复用已付回复**（PR #381 合并后）：新授权明确批准 `reuseBudgetRoots`，只复用完整身份匹配、已返回的直接付费响应；复用未命中时拒绝新增付费。
- **开跑前冻结代码。** 质检、校准、读法规则、截短校准都在机器质检实现哈希里。运行中途改代码，已签发的文本和音频放行证明就作废，所有语言都要重签。片段测试第二轮因此多花约 2.5 美元。
- **质检规则改变后，用新的 state 目录。** 修复账本会拒绝原样重筛已失败的候选（`blocked_prior_failure`），旧 state 留作证据。
- **同一候选不要反复重跑质检直到通过。** 质检失败的组，开新修订（Layer 2 重新翻译）后再质检。

## 规划器 v3 的可执行边界（#382）

本页的原始测量来自 #376 的运行配置文档；#382 将其作为机器配置的所属文档纳入。历史 75 次调用／语言不是当前逐句分组的容量保证。新周更授权使用 `sermon-canonical-layer2-budget-authorization-v3`／批准 v2，`ledgerScope=locale`，每语使用 8 MiB 账本；每语请求维度为 4,000，输入／输出维度按同一容量设置。金额仍保留用户给定的 5 美元建议，工具不擅自提高它：若实际执行配置的分组数连首次完整翻译＋复核轮次的五维保守预留都超过此金额，规划在写任何授权前拒绝，需操作者提供另行明确批准的 profile 和总额。请求额度够不等于美元额度够，也不承诺所有修复都完成。

新 QC 授权 v4／context v3 绑定一语的来源包、anchor、语言政策、环境、完整 OpenAI 路由（project ID、credential alias 及 configured-runtime 身份）、实际凭据的非秘密 SHA-256 指纹、当前质检实现哈希及来源哈希运行身份。`--qc-inputs` 指向 `sermon-machine-qc-inputs-v3` JSON（字段 `environment`、`openaiRoute`、`credentialSha256`、`source`、`anchor`、`policies`；`openaiRoute` 使用显式 launcher 的非秘密 `sermon-openai-runtime-route-v1` 五字段路由）；路径相对此 JSON，实际消费者从解析后的输入重算身份。文本和音频 QC 使用同一语言、同一根；不能用一语授权启动默认三语，也不能把它用于其他来源。

QC 上限还计入二级 `gpt-transcribe` 的保守预留：按已冻结的 transcription-request-v1 最多 180 秒／请求、每分钟 4,500 microusd 整分钟预留，片段 150 次另计 2.025 美元，周更 1,500 次另计 20.25 美元。它们与评判请求共用该语言的持久硬金额／请求／时限账本；不把进程内调用计数当总费用上限，也不把预留当实际账单。实际所有新 paid 请求均受合计 cap 约束。

`plan.json` v3 只给已选阶段签发授权。若全部阶段的 cap 加既有花费不适合总额，工具只给出串行建议，不写文件；显式 `--stage qc.ko` 或 `--stage layer2` 选择当前阶段。前一阶段有在途或未知结果时先对账，不把未知预留当结算释放；后续阶段需按实际剩余额度另行规划与批准。此工具不撤销旧授权，也不代替操作者关闭先前阶段或批准额外花费。

开工检查必须得到完整预期 commit 与实现哈希（显式参数，或来自所选计划）；检查器将重新验证授权、批准、计划文件哈希和实际输入。旧 plan v1/v2 与 profile v1 保留历史文件，不能重标为当前 plan v3／profile v2，需显式重新规划。#380 改变 API 评判身份，合并后首次运行用新 state／响应缓存，不从旧身份预算根复用，重新校准并生成新的放行收据。

计划 v3 的 `plan-approval.json` 冻结完整计划（包括总额、已结算费用、选定阶段及各授权哈希），`plan.json` 绑定该批准文件的哈希。修改总额、减少已用费用或重排阶段后，不能沿用旧批准；须明确重新规划与批准。预检核对整份 binding，不只重算一张可编辑的 schedule。

旧 scoped QC 授权 v2/v3／inputs v1/v2 保留原证据，须显式重新规划为 v4／inputs v3，不自动补 project 身份或重标旧收据。启动与每次调用按实际 launcher 路由复验；项目、凭据别名或凭据指纹变化须重新批准，不能沿用原授权重新购买同一质检请求。legacy unscoped v1 仅保留原合同，不称作新的 route-bound 计划。

`credentialSha256` 只记录已选择运行凭据的 SHA-256 指纹，不记录 key 值；可在显式 launcher 环境中用 `machine_qc_budget_authorization.credential_fingerprint` 生成。规划工具读取该非秘密指纹，真实消费者用当前环境中的凭据重新计算核对；不要将 `.env.openai` 或 key 值写入 inputs。

Layer 2 计划中的 `sizing.<locale>.initialReservation` 是按当前分组、翻译与复核角色及 `requestLimits` 计算的初始完整轮次保守上界，不是实测用量、提供商报价或账单。每次请求都预留完整 `maxInputTokens`（复核包含尚未生成的候选、规则、上下文与 JSON 序列化开销），以及输出与时间上限，再按冻结价格假设计入输入和输出费用。请求数、输入、输出、时间、费用任一维不足，规划器在写任何授权前拒绝；超大实际 payload 仍由运行时逐请求准入检查拒绝。规划器不会自动增加现有预算；需要缩小分组范围或提供明确批准的新 profile。

新 Layer 2 授权 v3 必须在显式 `run_with_openai_environment.py` launcher 内离线生成，绑定完整 `openaiRoute` 和实际凭据指纹。控制器启动、缓存读取及派发前均核验；跨环境、项目或 key 不能沿用原批准或响应。旧 Layer 2 授权 v1/v2 保持原冻结合同，不自动补字段。规划器 `--reuse-from` 作用于 QC 的明确批准预算根，不隐式迁移 Layer 2 缓存。
