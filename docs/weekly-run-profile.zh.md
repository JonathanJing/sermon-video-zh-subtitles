# 周更运行配置：并发、请求上限与预算预留

本页是正式周更和周六片段彩排的默认运行配置（2026-10-13 起）。数值来自两次真实运行的账本：

- 2026-10-11 周更全篇：461 句，三语。
- 2026-10-12/13 片段端到端：16 句，三语，dev API，账本在 `artifacts/clip-test-20261012`。

[本地生产 runbook](codex-local-production-runbook.zh.md) 按本页开工；需要偏离时记录理由。已冻结的 run 保留原配置，不原地改动。

## 结论先行

1. **瓶颈不在并发。** 10-11 周 12.5 小时里纯计算约 1.5 小时，其余是返工和等人（见[复盘](reports/20261011-weekly-release-resi-54475d42-retrospective.zh.md)）。片段测试同样如此：中途卡住的几次都来自预算预留用完、开工条件缺失和质检代码变更。并发再调高，节省的时间也只是分钟级。
2. **预算预留按最坏情况计，约为实际花费的 8 倍。** 每次请求都按请求上限预留，用掉的部分不退。上限给得不够，就会中途 `budget_exhausted` 或 `source_budget_exhausted`。片段测试因此停了三次：中文 Layer 2、西语校准、中英音频质检。
3. **Layer 2 的输出上限可以从 4096 降到 2048。** 实测 329 次 Sol 调用（10-11 周 220 次，片段 109 次），最大输出 623 tokens，p99 为 471。降到 2048 后，每次预留从约 0.058–0.063 美元降到约 0.038–0.043 美元，仍有 3 倍以上余量。超出上限的回复因 `finish_reason` 不是 `stop` 而判为不完整，该组按失败处理并走修复，不会放过截断的译文。

## 并发设置

| 环节 | 设置 | 说明 |
|---|---|---|
| Layer 2 翻译与复核（OpenAI API） | execution-v3 `layer2AutoRepair`：`groupWorkers: 8`；`maxActiveLocales`：正式周更 3，10 美元以内的 dev 测试 1 | 共享 job-root 的 API 槽位上限 24（[controller 合同](canonical-layer2-controller.zh.md#并发上限)）。三语同开时，三份预留同时占用预算 |
| 文本质检与校准（OpenAI API） | `run_machine_qc_clip_test.py --workers 8`；预算账本 `maxConcurrent` 16 | 只在 Mac 上调 API，不占 Spark，可以与另一语言的 Spark 环节重叠 |
| 配音渲染（Spark） | `--spark-production`：8 个常驻副本、每批 8 句、CUDA/BF16/SDPA | 全篇约 6–8 分钟／语言 |
| 静音压缩（Spark CPU） | 单任务 | 约 15 秒／片段 |
| 配音初筛 ASR（Spark） | `--batch-size 1` | 全篇约 3–4 分钟／语言。改用 batch 4/8 会改变 ASR 设置身份，需新校准，收益约 2 分钟／语言，暂不改 |
| 音频质检（Spark + API） | `--workers 4`，`--max-api-calls 150`；**与该语言的文本质检共用同一个预算授权（同一 `budgetRoot`）** | API 评判的回复缓存就是该授权的预算账本。换新的预算根会把文本校准的评判全部重买一遍：2026-10-13 实测每种语言多花约 0.3–0.38 美元、多 3.5–5 分钟（校准预取 211–288 秒，共用时 0.8 秒） |
| Spark 整体 | 独占会话内同一时间只有一个 GPU 任务 | 三种语言的渲染、初筛和音频质检依次进行 |

### 编排

1. 三语 Layer 2 同时开（正式周更）。
2. 每种语言的候选一出来，就在 Mac 上跑该语言的文本质检，不必等其他语言。
3. Spark 按语言依次做渲染 → 压缩 → 初筛 → 打包 → 音频质检。
4. 文本质检和 Layer 2 都只调 API，可以与另一语言的 Spark 环节重叠。

这样能省掉三语文本质检的串行时间，全篇约 10–20 分钟，但前提是所有开着的预算加起来仍在批准范围内。

## 预算预留怎么定

规则：**已结算花费 + 当前所有开着的预算上限 ≤ 批准总额**。上限按下表"预留"列设定，再留 20–30% 余量；一个预算结束后，只计它的实际结算。测试预算很小时，把花钱的环节一个接一个跑，每次只开一个预算。

每次请求的预留按上限算：Layer 2 每次约 0.038 美元（片段）/ 0.043 美元（全篇，2048 tokens）；质检每次约 0.011–0.0125 美元。

| 环节（每种语言） | 片段彩排 16 句：调用 / 预留 / 实际 | 全篇 461 句：调用 / 预留 / 实际 | 建议上限 |
|---|---|---|---|
| Layer 2（翻译＋复核，一次修订） | 约 32 / 1.2 / 0.22 美元 | 约 75 / 3.2 / 0.6 美元（10-11 周三语 220 次，实际 1.73 美元） | 片段 1.5；全篇 5（含一次修复修订） |
| 文本质检＋校准＋音频质检（同一预算根） | 约 210＋20–50 / 2.6 / 0.35–0.45 美元 | 约 1,450＋音频专有调用 / 约 20 / 约 2.5–3 美元 | 片段 3.5；全篇 30 |

片段彩排三语一轮实际约 2 美元（2026-10-13 分开预算根时为 2.69）；按上表依次开预算，最坏情况始终低于 10 美元。

## 开工条件（片段测试中实际卡住过）

- **Layer 2 需要 Spark 独占会话。** controller 在派发前调用 `production_spark_admission.require_session()`，没有会话时 job 直接失败（`spark_exclusive_session_required`），这一步发生在任何 API 调用之前。开工前 `spark_exclusive_session.py begin`，并在启动 controller 的环境里导出 `SPARK_EXCLUSIVE_SESSION_ID`／`OWNER`。
- **会话里某个 job 异常退出后，会话会进入 `reconcile_required`。** 先确认派发进程已经退出，并核对账本里没有处于 intent 阶段的请求；再用 `reconcile --job-id … --confirm-dispatcher-terminal` 清理，最后 `resume-begin`。
- **开跑前冻结代码。** 质检、校准、读法规则、截短校准都在机器质检实现哈希里。运行中途改代码，已签发的文本和音频放行证明就作废，所有语言都要重签。片段测试第二轮因此多花约 2.5 美元。
- **质检规则改变后，用新的 state 目录。** 修复账本会拒绝原样重筛已失败的候选（`blocked_prior_failure`），旧 state 留作证据。
- **同一候选不要反复重跑质检直到通过。** 质检失败的组，开新修订（Layer 2 重新翻译）后再质检。
