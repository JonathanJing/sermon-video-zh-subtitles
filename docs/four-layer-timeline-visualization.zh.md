# 每周四层制作时间线

用 [生成器](../scripts/build_four_layer_timeline.py)把同一次周更的进度账本、绑定同一账本身份的执行日志，和可选的 Dev 模拟计时画在分开的时间轴上。横轴为洛杉矶实际时间，纵轴为步骤；单击步骤可展开细分任务、前置依赖、可并行条件与实测实例。报告是本地只读 HTML，不上传讲稿或私人收据。

```sh
python3 scripts/build_four_layer_timeline.py \
  --ledger artifacts/post-live-runs/2026-09-27/drive-1wpixHcwnlS3WfOPdZ-oek_Y1YZG53NN5/four-layer-progress.json \
  --simulation artifacts/firebase-dev-four-layer-bucket-dry-run/2026-09-28-clip-03/candidate/simulation/timing-log.json \
  --out artifacts/four-layer-timeline/2026-09-27.html
```

以后每周替换 `--ledger`；没有模拟计时文件时省略 `--simulation`。输出保存在被 Git 忽略的 `artifacts/` 下。生成器不修改原账本，也不重新执行翻译、配音或发布。

## 时间含义

- **绿色实测条**：同一账本身份的 `stage_started` 到 `stage_finished`，或 Dev 模拟的 `startedAt` 到 `finishedAt`。失败尝试仍保留；未结束跨度不制造结束时间。
- **蓝／黄／红状态条**：进度账本显示 `running`、`waiting_review`、`blocked` 的连续时段。它们是状态占用时间，不代表计算用时或人手实际工作时间。
- **圆点**：只有完成记录，缺少开始时间。不能从前一层完成时间倒推该步骤耗时。
- Dev 模拟条属于预制片段的复用、打包及检查，不能拿毫秒耗时估算整篇模型翻译、逐单元 TTS 或人工听审。父阶段包住子单元时，重叠跨度不相加。
- **细分行“未计时”**是下一轮应采集的子任务；它没有时间条，也不代表零耗时。只有 `parentSpanId` 能追溯到同身份正式步骤的完整 `stage_started`／`stage_finished` 才会显示为该步骤的子跨度。名称或时间相近、但不属于该父跨度的其他账本不会自动并入。

细分任务仍属于原来的四层，不增加新的生产层或人工审批。当前针对最可能形成瓶颈的步骤设有 74 个细分行：

| 步骤 | 细分观察点 | 依赖与并行边界 |
|---|---|---|
| L1-02／03 | 转写、词级对齐、文本冻结；分句锚点、边界检查 | 冻结依赖转写和对齐；分段／风险片段可并行 |
| L2-02／03 | 每组初译、独立复核、失败组修订；覆盖、语言检查、准入 | 同组复核依赖初译；组与语言分支可并行，最终候选汇合 |
| L3-02／03／04 | 输入验证、模型加载、单元渲染、组装；解码、哈希、回转写；排程、字幕、编码 | 单元级工作可流水处理；GPU 合成并发须经实际资源与音质测试；完整音轨等本语言单元汇合 |
| L4-02／03 | 构建、逐文件上传；逐文件 GET／哈希、Range | 资产和语言可并行上传／核验；本周联合发布计划的 Catalog 指针更新是跨语言汇合动作，不归入任一语言的 L4-02 |

现有 `run_target_language_models.py` 和 `render_formal_target_language_speech.py` 已有翻译组、初译／复核、模型加载、逐单元与合轨 `accounting.stage`。新周次若启用 `SERMON_FOUR_LAYER_LEDGER` 并传入匹配的进度账本，这些嵌套 span 能自动进入时间线。其余细分名称是待埋点位置，需在对应正式 producer 内记录，不得用文件修改时间补造。

报告依赖关系只编码正式包门禁与发布顺序：Layer 1 英文审核 → 各语言正式 Layer 2 翻译；同语言文字审核 → Speech Job；同语言文字和音轨 → Release；Release → 上传 → HTTP 核验 → 客户端核验。Layer 2 策略、术语和经文可在 Layer 1 审核期间准备。中文、韩语、西语的同层任务可并行；某语言进入 Layer 3 无须等其他语言。Layer 3 的单元合成和筛查有流水并行空间，但正式完整音轨和听审仍须等该语言全部单元就绪。若当周发布计划要求三语一起上线，唯一可变 catalog 的更新必须等三语资产全部就绪；逐语言 Release 包依旧独立。

## 9/27 的已观测结论

- 正式进度账本有 46 个步骤；同身份执行日志仅覆盖 3 个步骤，另 43 个已完成步骤缺少可归属的完整执行跨度。因此目前不能计算可信的细分执行耗时排名或关键路径。
- 本次新定义的 74 个细分行中，9/27 正式账本有完整起止记录的为 **0**。这暴露的是计时覆盖缺口，不能据此判断真实瓶颈位于哪个子任务。
- Layer 3 排程步骤显示长时间 `blocked`：中文 18,531 秒、西语 18,530 秒、韩语 17,386 秒。它是最值得复盘的**状态区间**，应再查明其间是音频时长适配、正式听审、等待输入还是账本批量补记。不能直接称为排程程序耗时。
- Dev 模拟片段有 55 条细分计时；各语种步骤在模拟脚本里顺序排列，这证明**该脚本当次串行执行**，并不证明正式生产必须串行。可用它验证计时覆盖和画图，不用于估算整篇耗时。

下次周更要能真正找出最长执行环节，需要让每个正式 producer 在对应 `Lx-yy@locale` 下记录起止，并对翻译组、TTS 单元、合轨、上传和 HTTP 检查各自记录嵌套 span。人工审核应记录候选提交与收据决定时间；这个间隔可算等待时间，但不称作审核者工作时长。关键路径须使用明确依赖边和完整起止记录；覆盖不全时只列候选瓶颈，不输出伪精确的关键路径或并行节省分钟数。
