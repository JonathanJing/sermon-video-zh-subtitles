## 重新评估：替换完整职责才有价值（2026-10-06）

用户已明确：程序能确定的判断继续用程序。后续不再开展Decisions替换程序的A/B。已完成的规则对照仅作为历史记录；两轮配置、authority和收据保持冻结。以下优先级是本次代码复核后的研究建议，不是已验证的收益或已生效生产政策。

**目前没有证据支持把Decisions接进每周主流程。下一项只优先研究E01独立英文裁判的整体替换可行性。** 给既有流程增加标签调用，只有真正省掉原来的工作、同时不增加漏检与返工，才有价值。

| 任务 | 实际职责与新判断 |
|---|---|
| E01 英文断句裁判 | 当前Sol只判断、不改写，是最接近可独立替换的现有付费角色。但现行收据需要书面evidence／unresolvedIssues，消费端绑定实现hash及模型／effort，Decisions标签不能直接充当同合同收据 |
| E02 翻译独立审核 | Sol同时审核、修稿、输出覆盖及证据；前置Decisions后仍调用完整Sol，会增加工作。取消这项优先级，暂不扩大标签实验。若以后拆分审核与修稿，须另评完整架构和准入合同 |
| E03 模糊修复分流 | 有限动作选择在任务形态上适合，但目前没有默认付费模型responder。仅在真实人工定位／选择时间构成瓶颈时，另立人工直接处理与辅助处理实验；尚无收益证据 |
| E04／E06／E08 | 文本听审排序、大纲／默想审核、反馈分派属于人工辅助或新增能力。当前没有减少整轨听审／人工审批、或替换同任务模型调用的证据，暂不并行扩展 |

### E01新增复核证据

复核两轮E01的B receipt：首轮12/12、扩展48/48，**共60/60均至少有一项needs_more_evidence**。若任何该标签都回退Sol，这批样本没有任何一句可省掉Sol检查，还会增加Decisions请求；这是特定回退策略在旧样本上的推演，不是已运行的完整链实验，也不证明Decisions不能胜任其他题目设计。

原裁判判断的是“切分是否引入语义损失或新歧义”，明确不因原完整句已有歧义而失败。B增加了证据不足选项，必须重新核对等价任务和上下文；不能用0/60完整标签吻合率直接判断准确率。现有测量按单句调用，生产默认每批15句；6秒与0.3秒的单次速度差不能推导整篇节省。

证据入口：[裁判任务与默认批量](../../scripts/judge_english_source_for_translation.py)、[收据消费及身份检查](../../scripts/build_english_source_package.py)。60/60计数来自已冻结的ignored原始receipt，不新增请求或修改原结果。

### 下一轮只验证E01完整审核终点

1. **先对齐任务（45分钟准备／复核块）**：冻结相同完整句、切分单元、相邻上下文和现行rubric；程序继续负责身份、覆盖及确定性时间检查。双方判断同一“切分引入的问题”，统一弃权处理与可接受答案。独立人工标注，覆盖正常句及否定、数字、引语、跨单元依赖的严重阳性；在质量留出前冻结方案。
2. **比较真实批量（45分钟在线观测块）**：A使用原生产裁判的15句批次；B使用等覆盖的Decisions方案，含弃权、解释所需Sol回退、结果校验和证据形成。若不能产出满足拟议审核合同的证据，记not_contract_equivalent，不把标签当完成。新的Decisions收据及政策必须明确版本化；此PR未修改生产合同。
3. **通过质量后再跑完整片段（60分钟隔离观测块）**：按原计划至少5个独立来源及独立gold，先完整片段再整篇canary，测机器审核终点、实际Sol调用减少数、总费用、回退率、人工active分钟和返工。上述时长是观测块，不保证在该时间内完成独立标注或统计验收。
4. **继续／停止**：保持原质量与收益门；不按便宜或单次快判胜。若等价任务下B仍频繁弃权，或含回退与证据交付后不能省掉原工作，停止接入研究；有实测收益才提出生产合同变更。

本次只完成代码／历史收据复核和实验重设，没有新增API调用、生产变更或新质量结论。已有API估算消费仍为$1.950457／$20，剩余授权无需为扩大无等价终点的标签样本而用完。

## 原始八环节基线清单

| 环节 | 真实基线 | 实验含义 |
|---|---|---|
| E01 英文审核 | 程序硬检查 + Sol 6.1 high，输入为文本／时间元数据 | 可对比机器判断；不包含听音频能力 |
| E02 翻译审核 | Sol 6.1 medium 会修正译文后返回 verdict/evidence | 必须分开比较标签与完整修订交付，不能把 final pass 与原草稿的 B 判断直接相比 |
| E03 修复分流 | 规则路由；歧义分支只有 proposal 接口 | 不存在既有默认 Luna responder；歧义分支另作人工辅助对照 |
| E04 配音筛查 | 共用 ASR 后，相似度／短句规则 | B 比较文本差异判断；队列排序 A 为原单元顺序，无已核验语义 ranker |
| E05 时长判断 | 确定性 scheduler／算术诊断 | 识别试验输入原始 measurements，移除 A 答案；如何修复另以人工选择为 A |
| E06 大纲／默想 | 生成模型 + 结构／引用程序校验 + 人工审核 | 无独立自动语义 triage 基线，需人工直接／辅助试验 |
| E07 异常／Supervisor | provider 规则；Luna CLI 选 allowlist，程序验证 | 规则、Supervisor、模糊人工诊断分层；不合并成全面根因分类器 |
| E08 反馈 | 用户类别 + 程序入库 + 管理员人工处理 | 无自动评论分类基线；用户自选类别不是 gold |

## 设计及证据边界

详细方案见 [配对 A/B 设计](../decision-api-weekly-ab-design.zh.md)；机器计划见 [v1 plan](../../config/decision-api-weekly-ab-plan-v1.json)。

- 同一冻结输入，AB/BA 交错，逐环节报告。
- 证据准备、请求、有效验证、人工 active／wait、修订返工分别计时。
- 12-case 协议 smoke → 20-case 校准 → 至少 60 独立真实案例；pilot 是探索性结果，之后扩大及做 10 分钟／全长 canary。
- 二元质量不能用零分歧退化 bootstrap 宣告非劣；标签更快而完整产物不等价不得判全流程胜出。
- historical cache、模拟响应、live 请求、provider usage、估算成本和人工 gold 各自记录。
- 605 秒来源样本只有历史模型判断，不能当独立 gold 或新 API 时间；9/20 音频 11 个 flags 全部人工批准，缺严重异常阳性样本。

## 扩大样本的实际范围

- E01 可核验114句，但只有一个605秒来源。按同来源扩大到60句，保留已有12句结果，不重复派发已成功配对。
- E02 找到108个不同输入、三种语言、多个诊断 run；它们仍是同一个 source package。新 Sol API测量保留原 medium／fast，不把历史CLI时间当API基线，不把诊断审核宣称为完整生产准入。
- E04 可复用9/27整轨419个ASR单元、28个flags；flags不自动是错误。扩大抽样只测已冻结文本差异，不重做ASR或把它称为听音频实验。
- 目前达不到预注册的≥5独立来源要求，标记 sample_gap；run、语言和音频修订不增加来源数。
- E06／E08及其他人工辅助子任务需建立人审 A、独立 gold 和 active/wait计时，尚无胜负。机器证据不代替人审批准。

本轮选择：E01／E02保留Decisions辅助分流的研究候选，继续保持现行审核链；E03／E05／E07已知规则继续用程序，E04保留程序筛查及整轨人审，E06／E08另建人工直接／辅助面板。没有发布、审批或生产策略变更，也没有声称现场／设备验收。
