## 5. 最短路径

### 5.1 T0 之前（视频到达前）

1. **先定架构**：默认一个 family 页面，中文默认，三语 target 各自绑来源。不要等页面上线后再改。
2. **冻结已批准文本**：416 组人工批准稿按新 source hash 机械重绑；只复核变化的组，不重跑模型。
3. **预生成 family 候选骨架**：页面、content、captions、study 三件、`videoDelivery`、feedback alias 先预检。
4. **预生成海报/公告**：pageId 已知，主视觉复用，二维码指向 family。
5. **预热 Spark + 预建 speech job**：视频 hash 一到就能提交。
6. **预检包**：`tongxing_production` import、`bash -n`、内存计划、compact 容器里的 `ffmpeg`、镜像输入。

### 5.3 人审口径

中文音轨 08:56 完成，用户 08:59 批准，间隔 3 分钟；但音频收据写的是 `fullPlayback=approved`，文本摘要也写“配音经人工完整试听”。33 分钟的整轨不可能在 3 分钟内听完。两种解释：

- 用户是**抽样/信任既有音色**后批准：那标签应是 `spot_checked`，不能写 `fullPlayback`。
- 用户确实另找了时间全听：那收据时间应绑定实际听完的时刻，而不是 08:59。

这不是抠字眼：**全听是唯一不能并行压缩的 33 分钟**。如果要求 `human_reviewed` + `fullPlayback`，最短路径就是 79 分钟；如果接受抽检，才能做到 49 分钟。两者不能混写。
