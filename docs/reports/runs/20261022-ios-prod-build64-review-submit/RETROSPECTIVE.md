# 复盘：20261022-ios-prod-build64-review-submit

## 结论先行

用户回复正式 App 构建 64 真机检查“正常，提交审核”后，App Store Connect 已接受 iOS 1.26.21（64）审核提交。提交与版本均读回 `WAITING_FOR_REVIEW`，发布方式仍为 `MANUAL`。这是审核排队状态，不是批准或上架。

## 总时间

创建提交草稿、添加唯一 App Store 版本项目、最终提交均获 Apple 2xx 响应；提交时间见 outcome.json。没有模型调用、付费推理或重新构建。

## 各层模型、耗时与速度

L1–L3 未执行。L4 为 App Store Connect 审核提交与状态读回，无模型、token 或费用。

## 错误

第一次提交前只读核验因未请求 API 的 relationship 字段而失败，未发出提交写入；改用 `include=appStoreVersion` 后核对唯一版本项目、构建 64 与手动发布设置，再提交成功。

## 可以改进的地方

把审核项目的 `include` 参数写进提交前核验脚本，可避免只读预检的字段缺失；由 iOS 发行维护者跟进 PR #1301。

## 实际覆盖范围

覆盖 Apple 审核提交及读回。用户报告真机检查正常，但没有真实生产 APNs 锁屏接收回执；提交后服务器只读计划仍为零个有效订阅，已询问用户 App 内订阅状态。审批、上架、群发和现场验收未执行。

## 遗留状态

审核排队中。正式版推送的真实设备登记和单设备投递待查；所有私有凭据、设备标识和原始 API 日志留在本地忽略目录。

## 外部可见的变化

Apple 审核队列中有 1.26.21（64）；商店用户尚未获得新版本。
