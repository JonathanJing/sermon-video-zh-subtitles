# 复盘：20261126-weekly-auto-poster-dev

数据见同目录 INDEX.md 和 manifest.json。这是周六自动流程海报这一段在 Dev 站点上的第一次真实上传，接着同一天的发布演练（报告 `20261126-weekly-auto-publish-dev`）：同一页 `revelation-jesus-will-return-20261122`，同一个演练用的生产记录。海报的前半段（概念草稿、主视觉、三语合成）当时已经跑完并停在海报审核步骤，这一次从批准走到回读。

## 结论先行

- **交付类型**：测试。Dev 站点上的一次真实部署（海报和公告清单），不是正式发布。
- **最终状态**：海报阶段 `uploaded`，部署 `deployed`，回读通过。生产记录仍停在等发布后确认（没有人在手机上看）。
- **证据边界**：
  - 批准是用户在会话里给的（「在 Dev 实跑上传」，只限 Dev），由代理按原话记到海报这一步上，不是用户在审核页上点的。
  - 用户在会话里只看过这张海报的中文预览；韩语和西语海报没有人看过。可是海报收据按审核页的规则，把三种语言都记成了人工看过（`visualReview.humanApproval=true`，审看人写的是「会话里的回答，由代理记入」）。这是演练记录方式造成的，正式运行里审核人要在页面上勾「我看过选中这一张的三种语言」才能批准。这几份收据已经随公告上了 Dev，没有改。
  - 主视觉的画面内容没有人做过语义审核；起草模型选的概念和它自己的打分只是机器结论。
- **没有覆盖**：正式站点上的海报上传；App 里显示这条公告；重画、换概念的第二轮；生产机 mbp16 上调用 Codex CLI。
