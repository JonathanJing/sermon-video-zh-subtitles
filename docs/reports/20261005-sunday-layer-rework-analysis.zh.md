按片段恢复的两个实际限制：

- TTS batch8 保持完整窗口与 seed 身份。只缺一个输出时可能重放整个 8 句模型窗口，仅取缺项，保留已提交邻居的字节；改一个句子的文字／指令时，窗口输入身份可能使同窗全部需新输出。不能临时缩成 batch1 却称同身份恢复。当前 `_BatchedUnitSynthesizer` 见 `render_formal_target_language_speech.py:705`。
- ASR 同 job 有逐单元 cache，能只补缺项；但请求身份包含整份 speechJobJsonSha256。跨新 job 的未变单元，现有代码也不能直接沿用旧 ASR cache，需新增显式迁移证明。见 `screen_target_language_audio_units.py:130`。音频变动还要求重审变化的声学内容，全文人审绑定不能自动复制到新整轨。

ASR 相似度低本身不要求重合成：若是识别错误，仅记录有绑定的听审裁决；波形有错回 L3，译文有错回 L2，英文／锚点有错才回 L1。当日韩／西疑点有整体批准，但缺逐项声学结论，不能称全部是误报。当前 quarantine／assembly-only 是现行恢复能力，不是周日已通过这些通用入口执行的证明。

单元音频变化后后续排程可能连锁变化，所以同语言整轨、cue、manifest、Audio Package 和整轨听审／同步证据仍要重新闭合。这与所有单元重新 TTS 是两件事。

## 哪些只重片段，哪些要整层，哪些会回到上游

| 触发变化 | 模型计算的最小范围 | 必须重建／重验的完整范围 | 是否回退上游 |
|---|---|---|---|
| 请求/进程失败，输入和身份不变 | 对账后只补未完成；unknown 暂不重发 | 本层最终汇总与缺失收据 | 不回退 |
| 单组译文语义错误 | 该组及实际依赖其修订的上下文组，走完整译审链 | 同语言 L2 候选、L3/L4 正式包；匹配的旧计算需验证迁移 | 回 L2，不回 L1 |
| 单元波形损坏／合成异常，文字正确 | 单元或受生成身份约束的 batch 窗口 | 同语言排程、整轨、ASR/听审、Audio Package、release | 回 L3，不回 L2/L1 |
| 仅静音处理／同步参数变化 | 无需翻译／TTS；变化音频的 ASR 依当前 cache 身份处理 | 同语言整轨与 L3/L4 证据 | 留在 L3；参数例外需精确授权 |
| locale 全局规则、模型／prompt 改变 | 审计每组实际 payload；所有请求变化且无迁移证明时整语言新算 | 该语言 L2–L4 | 回 L2；不自动影响其他语言 |
| voice/checkpoint、TTS 模型／生成身份全局改变 | 所有受影响单元／窗口，可能全语言 TTS | 该语言 L3–L4，音色能力／听审证据 | 回 L3，不自动重译 |
| 英文事实、证道窗口、锚点真正改变 | L1 受影响内容；当前 global manifest key 可能要求全批重审 | **所有语言 L2–L4 正式身份与批准失效**；旧计算能否复用须显式证明 | 回 L1 |
| 仅页字段／环境／上传／HTTP／L4绑定变化 | 无上游模型调用 | 受影响 page＋locale＋environment；重聚合共享索引 | 留在 L4 |

合同依据：[四层失效规则](../multilingual-production-interfaces.zh.md#数据流与失效规则)。源包或候选审核封装改变也可能改变正式身份，但不必然改变模型实际输入；这种情形需要重新验证／绑定，不能自称审批仍有效，也不能自动清空所有模型结果。当前没有通用跨版本局部迁移覆盖所有入口。

“整层重做”应明确写成整层**模型再生成**、整层**包重建**、或整层**验收重跑**。只有全局依赖确实改变了每个请求、缓存证据不可信，或无法证明安全复用时，才把模型再生成扩大为整层。不同语言独立失效；发布计划要求三语一起只会扩大等待／交付范围，不自动扩大模型返工范围。

局部英文修改还要检查消费该源句的上下文组。当日 L2 已提供前 3／后 2 个 English source unit，远距离关系仍需明确 brief；不能只重改字所在组。目标语言文字修订则不机械扩大到前 3／后 2，须看实际 payload 是否消费了修改内容。

## 下次发现异常时的处理顺序与开发缺口

1. 先冻结异常 WAV／payload／stderr／输出身份，区分内容错误、基础设施失败、结果未知和校验器错误。周日旧 u172 WAV 缺失使根因不能补判。
2. 比较内容、上下文、规则、模型／运行时和审核绑定，列出变化组与依赖组。不要依据新目录、commit 或一个总 hash 直接选择全量生成。
3. 输出只读 recovery plan：已有完整结果、需重新验证、需重新计算、unknown 待对账，分别计数；每组说明不能复用的原因、batch 窗口和下游失效范围。
4. 模型只补计划中的缺项／修订项；缓存重组用明确 assembly-only 路径。先修最早异常源，再重算整条排程，避免把后续 lag 全当成后续译文过长。
5. 重建包和审核绑定，重新核验实际环境。release/HTTP收据不可随资产复制成“当前完成”；保留旧证据作为历史。

优先推进：核验已实现的 L1 统一 cache namespace＋single-flight 在所有生产入口启用，取消剩余手写 prewarm；模型实际输入身份与包审核身份分开审计；安全的 L1/ASR 跨版本逐片段迁移；通用 changedGroups/batch recovery plan；已冻结上下文的 receipt 快路径；发布环境／attempt 独立收据。现行 `english_source_judge_cache.py` 已有同 root、flock 和 started/unknown 保护，不能继续将全部缓存基础能力列为未实现。这里只提出剩余覆盖与验收方向，没有运行优化后的实际生产对照或测得节省量。
