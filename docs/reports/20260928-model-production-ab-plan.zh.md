# GPT-6 模型分工与每周生产核验实验计划

日期：2026-09-28。分支：`codex/model-production-experiments`。状态：模型调用与自动核验完成；人审评分待审核者填写。实测见[结果](20260928-model-production-ab-results.zh.md)。

## 目标与边界

分开回答两个问题：

1. 在相同脱敏生产状态下，Agents API 的 Sol 或 Luna 是否能正确定位下一步、阻断缺失证据，并节省人工排查时间？
2. 在相同已审英文源、分组和语言政策下，更换 Layer 2 **初译模型**是否能在不增加关键语义错误的条件下降低延迟或费用？

实验只生成 shadow 证据，不写生产审批、正式 Layer 3/4 包、目录、GCS 或 Firebase。正式 Supervisor 仍以本地确定性状态为准；正式 Layer 2 仍以 Astra 初译、Sol 独立逐组复核为准。模型 session `completed`、机器复核 `pass` 与正式交付状态分开记录。

## 冻结与记录

- 固定仓库 commit、实验脚本 hash、模型 ID、reasoning effort、prompt、工具定义、输入规范 JSON hash、语言政策各组件 hash、分组与运行顺序。
- 每臂独立 Git ignored `artifacts/model-production-ab-20260928/` 子目录，保存原始请求／响应、request/session/turn ID、开始与结束时间、状态、可得 usage、缓存命中与失败恢复标记；不可得数据记 `unknown`。
- Git 只保存代码、无原文和凭据的 fixture、脱敏汇总与人工判分模板。原始讲稿、译文、个人数据和 API key 不进入 Git。
- 每个 live 请求先做模型访问预检；错误、超时和未确认付费响应不得自动以新身份重试。记录实际请求量，费用按请求时官方价格快照另算，不能用 token 数直接推断账单。

## E1：Supervisor 核验助手

- A：`gpt-6-sol` / `medium`；B：`gpt-6-luna` / `medium`。同一 Agents API、只读工具、指令和脱敏状态，交错运行。现有确定性状态机给出预期动作，不作为模型臂。
- 样本含正常完成、等待来源、缺窗口审批、来源／审批 hash 不符、活跃租约、QA 失败、发布 HTTP 已通过但设备／现场未验收、工具失败／中断与重复调度。每例先冻结预期 action、阻断项、允许工具和状态。
- 指标：关键错误放行次数、正确阻断／升级率、误阻断、工具调用及拒绝、session 终态、p50/p95 墙钟、usage／费用、审核者定位分钟数。关键用例错误放行必须为零；其余指标报告样本数和波动，不以单次快慢切换默认模型。
- 先离线 replay 与现有 validator 测试，再做有界 live shadow。live 阶段不得调用 mutation 工具。

## E2：Layer 2 初译模型

- A：Astra 初译 → Sol 独立复核；B：Sol 初译 → Sol 独立复核；C：Luna 初译 → Sol 独立复核。同一实验只换 translator；reviewer、prompt、术语／经文政策、source units、group plan、`workers=1` 和 reasoning effort 固定。模型不同使实验 policy hash 不同，旧批准不可复用。
- 先用已审 2026-09-20 的 178 秒片段做可重复性试跑，再扩展至 `zh-Hans`、`ko`、`es` 的同源片段；若整篇已审来源和政策齐全，再跨周次扩展。缺一项就记录覆盖缺口，不用未审来源冒充正式样本。
- 自动指标：source-unit 完整覆盖、组顺序、schema／语言插件、模型复核 fail／uncertainty、请求完成率、p50/p95 延迟、整 locale 墙钟、输入／缓存／输出 token 与费用。
- 匿名评分材料打乱 A/B/C 顺序。语言审核者按英文逐组标记遗漏、否定／数字／专名、经文／引语归属、新增含义、自然度与修订分钟数；分歧另记裁决。已有批准译文可作参考材料，但其相似度不是人审或正确性的替代。
- 候选只有在关键语义错误不高于 A、没有新未检出的严重错误，且费用或耗时有实质收益时，才提出新生产 policy；最终仍须该新候选的全文人工批准及后续音频／发布门禁。

## 阶段与退出条件

| 阶段 | 产物 | 退出条件 |
| --- | --- | --- |
| 0. 分支和样本盘点 | commit、样本身份、权限预检 | 所有输入 hash 可核对，原始材料仍在 ignored 目录 |
| 1. 离线实现 | 两个 shadow runner、fixture、定向测试 | 故障及恢复用例通过；正式入口无行为变化 |
| 2. E1 live shadow | 逐次收据、汇总 | 所有声明样本得到终态；关键错误零放行或明确失败 |
| 3. E2 live shadow | 各臂逐组原始收据、匿名评分包 | 每个成功组有请求及用量证据；失败组原样留证 |
| 4. 评价与报告 | 脱敏比较表、缺口和建议 | 自动分数与人工评价分别标注，结论只覆盖实际样本 |
| 5. 保存与核验 | commit、远端分支 | `git diff --check`、定向测试、远端 commit 回读通过 |

如需母语审核者补充人工判分，先完成所有可独立取得的模型响应和匿名工作表；只有收到真实审核决定后才能填写人审列。

## 已有基线及限制

既有 [Layer 2 韩语 A/B](20260923-layer2-astra-sol-gemini-ab.zh.md) 的 14 单元和 178 秒片段可用于选样，但缺可复现的 API 用量与延迟，不能直接作为本次成本／速度 A。既有 Luna/Sol 调度小样本的速度差小于波动，最小循环还有模型状态未被确定性校验接受；本次必须重新跑同条件对照。
