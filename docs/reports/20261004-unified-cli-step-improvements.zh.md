# 从整体 CLI 到每一步的改进

日期：2026-10-04（洛杉矶时间）。本文把 [统一 CLI 设计审核](20261004-unified-cli-design-review.zh.md) 拆到命令和每周生产的每一步。设计原稿 [统一 CLI 与持久化执行设计](../unified-cli-pipeline-design.zh.md) 的 SHA-256 `1cea7a50f3bdd83dd76c356a9b9bc89aabf3136d564026746591e9ddab5288fc` 保持不变。这里写的是下一版验收应如何落到每一步，不是已实现的命令。

已明确的完整目标仍是：译文、配音、大纲、默想都经过各自审核，双测试端人工查看通过后，再分别进入 iOS 正式与 Firebase 正式的内容验收。设备和现场、PDF、海报、每周商店二进制按各自约定记录，不由这份技术审核改掉。首轮 canary 只有在授权者明确缩小 `completionScope` 时，才可以先停在单语、译文或 Firebase 读者。canary 完成不等于 `dual_production_verified`。

## 整体 CLI

人提交一次意图，然后只在五个内容门出现：窗口、英文源、译文、整轨听审、发布授权。其余转移由单一 owner 根据收据推进。对话退出后 worker 继续。到达本周完成范围后，owner 停止生产派发。

| 命令 | 改进后的行为 | 这一步去掉的人工 |
|---|---|---|
| `run plan` | 只读。一次做完下面的预检，返回 blockers 和 planHash。不建 job，不读密钥，不占预算 | 人不用先跑起来才发现读上限、模块或错源 |
| `run submit` | 重验 planHash 后原子冻结 manifest。派发前失败记为 `blocked`，不关闭一个付费父运行，manifest 未变也不重新确认预算 | 每次预检失败都重新授权 |
| `layer submit` | 同一 manifest 上提交某一层、某一语。上游收据不齐就拒绝 | 手工指定层号跳过源或人审 |
| `job status` / `job result` | 只读五维状态：process、artifact、review、publication、device。进程成功不改写人审或发布 | 把上传成功说成页面已交付 |
| `job wait` | 等到 `human_pending`、终态或调用方给出的期限。超时只结束等待 | Agent 每 30 秒把长日志读回会话 |
| `review ingest` | 校验审核者、范围、revision、候选或音轨哈希后写入。布尔值和自由文本不能变成批准 | 人在会话里口头说「通过」 |
| `job resume` | 只按当前收据重新检查门禁 | 用 resume 清空 unknown 或扩大预算 |
| `job reconcile` | 证据齐全才写恢复收据。未知的已发出请求保持 unknown | 把未知请求改成没执行再重付 |
| `job cache-recover` | 只消费已经完整返回的响应，强制无 API | 候选没落盘时整篇重译 |
| `worker drain` / `job cancel` | drain 停新准入并等在途结束。cancel 不能撤回已送出的 API | 删目录后重跑 |

owner 的循环固定为：前置齐备 → 资源许可 → 派发 → 收据验真 → 下一节点。两个 owner 竞争时只有一个拿到有效派发权。`cacheHits` 只在命中了真实响应时为真，同时分开记录 `reused_groups` 和 `fresh_api_attempts`。中文 r12 那种 602 组复用、字段仍为 0，以及「只传了复用目录却标成命中」，都要在夹具里失败。

`run plan` 在第一笔 ASR 或翻译之前返回这些项，缺一项就是 blocker，新增付费为 0：

- 媒体、窗口、当前源包、锚点、逐语 policy、prompt、plugin、模型和 checkpoint 是同一份身份。目录名里的 approved 不能当身份。
- 对齐文件、冻结 plan 和 linked history 的读取上限盖得住实际字节。256 KiB 私有读取器拒绝 616 KB 对齐文件这种失败留在预检。
- 本轮会加载的模块已经列入闭包。延迟导入造成的代码身份变化在 submit 前暴露。
- runtime、checkpoint 和 `sox` 导入在加载模型前检查。
- 主机名和临时路径写入 provenance，不单独使内容或已有批准失效。适配器实现哈希属于执行准入身份：被调用的校验或执行依赖变了，就停止新派发。历史产物保留，身份不兼容时 `blocked`，新增付费为 0。稳定依赖、文本或媒体变了才使内容失效。
- 预算上限存在。unknown 请求继续占着预留，不能换目录绕过。
- 同一种请求错误在第一组失败后停止该语其余组。

状态示例保持设计里的形状：某一语的 Layer 2 job 可以是 succeeded，整次 run 仍是 blocked，原因是 `translation_review_required`。音轨可播、交付检查阻断、HTTP 已核验分三行显示。

## 逐步改进

下表是每周主路径。自动列由 owner 执行。人列是这一步仍然留下的决定。

| 步 | 自动推进 | 人留下的决定 | 完成判据 |
|---|---|---|---|
| 1 素材与范围 | 计算媒体哈希、时长、解码，复用已核验文件 | 选定来源、语言、预算上限、本周完成范围 | plan 返回 planHash，付费请求为 0 |
| 2 证道窗口 | 用原录像时间生成审核表，绑定媒体哈希 | 批准一次窗口。绑定未变就沿用 | 审核表时间与源时间一致，不重复索取 |
| 3 转写 | 记账后发一次 ASR。未知结果走对账 | 低置信专名、引语和独立转写冲突进入短复核队列 | 转写收据绑定媒体与窗口。冲突未裁定则停在源，不开始翻译 |
| 4 英文检查与对齐 | 一次英文文本检查。MFA 比对稳定依赖，主机和适配器另记 | 锚点切不开、或英文包需要改正时才审 | 源包 `translationEligible` 只在英文批准后为真 |
| 5 译文调度 | 列出的语言同时进入 Layer 2，组内先 Astra 后 Sol。单语 canary 通过前，并发不超过现有上限 | 无 | 错源在第一笔翻译前被拒。三语读到同一当前源 |
| 6 一组的机器链 | 生成、独立复核、语言插件按冻结 payload 执行。失败组开新修订，其余组新增请求为 0 | 机器修订后仍失败的组才进入审核队列 | `reused_groups` 与 `fresh_api_attempts` 和真实响应一致 |
| 7 译文批准 | 批准写入后，该语立刻取得正式配音资格。其他语继续翻译 | 审队列里的组，并决定是否批准该语候选 | 收据绑定 candidate 哈希。豁免保持 `humanApproval=false` |
| 8 配音 | 声音、checkpoint、种子和文本未变的单元直接复用。变了的单元重合成，然后重排整轨。模型保持加载 | 无 | 未变单元重新合成为 0。加载、推理、写盘、收尾分开计时 |
| 9 回转写 | 全覆盖筛查。机器差异保留为待裁定，不改写成配音失败 | 裁定队列中的单元，绑定被听音频的哈希 | 旧音轨的裁定不能批准新音轨 |
| 10 听审与同步 | 标出超时和与原片的时长差。自然语速排程，不做时间拉伸 | 首次或时间线变化后的 1 倍整轨听审，加上疑点 | 听审收据绑定当前音轨。缺整轨证据不能发布 |
| 11 发布与读者 | 用完整基线组装，拒绝过期快照。先上传不可变资产，再更新目录。核验列表、打开、起播、字幕和换语。正式状态只来自验过的读回收据 | 一次发布授权。完整目标还包含大纲、默想和双端内容验收 | 约定 scope 内 `http_verified` 与 `device=not_checked` 可以同时成立。传入的 observation 不能自己宣称正式发布 |
| 12 停止 | 当前 manifest 的完成范围满足后停止该范围的生产派发，冻结收据 | 海报和改代码另开任务。完整目标未完成时，大纲、默想和另一端发布仍是后续生产范围 | 之后的工程 token 不写回已停止的那次运行。canary 停止不把缺项写成最终完成 |

### 1. 素材与范围

`run plan` 读取来源、语言和完成范围，给出规范化预览。已下载且哈希相符的媒体直接复用，计划里写明复用了哪个文件。source URL 哈希缺失时，计划把来源标成「媒体哈希已核验、链接未核验」，不把空链接写成已验证。

人在这里确认预算上限和本周要交付的语言。确认之前没有 reservation。

### 2. 证道窗口

审核表用原录像时间。9 月 23 日曾把证道相对时间再加一次起点，首句错成 40:29，同一窗口被人再确认了一次。改进后的表由冻结时间线生成，人只批准一次。媒体哈希和起止时间未变时，`review ingest` 接受原收据，owner 进入转写。

### 3. 转写

转写走付费账本：先记 intent 和预留，返回后记 usage，验真后才让对齐开始。未知结果保持 unknown，`job reconcile` 只能去查原请求，不能再发一次。

播客在译到 `0-u083` 才发现 `quote-unquote secular` 被写成专名，已经发出的 88 组中文不能沿用。改进后，冻结翻译前先把低置信专名、引语和互相冲突的转写收成短音频队列。人只听这些片段。裁定产生新的源 revision，未变的对齐保留。队列未空时，Layer 2 不派发。

### 4. 英文检查与对齐

英文文本检查是一次模型调用，和转写分开记账。对齐比较稳定依赖文件。10 月 1 日新鲜重跑里，新的适配器哈希正好等于当次冻结的对齐脚本，主机名也是当次执行记录，交付仍被 `fresh_delivery_source_mfa_changed` 挡住。改进后主机名写入 provenance。适配器哈希继续参加执行准入：它等于本次冻结的生产者时记为本次执行，不把整份 runtime 判成内容漂移；依赖文件仍要逐项复验。未知或被替换的适配器继续拒绝。

锚点过长且没有安全切点时停在 `waiting_anchor_review`，像 9 月 23 日 13 秒和 10 秒的单元那样。人不需要为了换主机重审英文。英文批准之后，源包才是 `translationEligible`。

### 5. 译文调度

owner 从运行清单取当前源，不从目录名挑选最新的 approved 包。播客 ES/KO 五轮 3362 次调用打在旧源 `8980bbb3…` 上，正式源是 `de074b67…`。这个差异在 `run plan` 就返回 blocker。

列出的语言一起进入机器翻译。组内顺序仍是 Astra 初译，然后 Sol 独立复核。跨组并发先用已经冻结的上限。单语 canary 的质量、失败率和预算有对照之前，不把 24 路并发提升成默认。三种语言依次打满 24 路，不能写成已经并行。

政策、Astra/Sol 提示词和插件从同一份冻结政策生成。精确引文的范围写在请求里。播客里通用提示要求全部直接引文用固定译本，已批准政策只对启示录 5:9 的限定片段精确引用，Sol 因此多次停跑。术语表面单独成表：只改一个译名时，失效范围是源文命中该术语的组。9 月 30 日 World War 的目标表面一改，政策哈希变了，三语 13 组全部重译。改进后，未命中的组保持原请求哈希，可以复用。

### 6. 一组的机器链

每一组的顺序是生成、复核、插件。owner 不等待会话决定下一条命令。

- 结构失败留下安全代码和原始响应哈希，按已知 usage 结算。缺 usage 就保持待对账。不自动重发。
- 同一种 HTTP 400 在第一组出现后，该语其余组不再派出。9 月 30 日 39 组全部 400 就是这条要挡住的路径。
- Sol 判 `needs_rework` 时，只为该组开带父修订的新修订，再走 Astra、Sol 和插件。10 月 1 日中文 `fresh-g012` 多了 2 次请求，其余组没有重付。这是目标行为。
- 插件拒绝先把失败收据写稳，再进入修订。中文 r10 有 1678 次请求完成后 26 组被插件拒绝，修复应只派发这 26 组和上下文受影响的组。
- 恢复时分开计数。r12 是 602 组复用、237 组新请求、474 次 API attempt。`cacheHits=0` 不能再代表这次复用。只传了复用目录、组上没有命中响应时，命中标记为假。

机器链结束时，候选是 `human_review_pending`，`releaseEligible=false`。

### 7. 译文批准

审核队列只列出插件失败、Sol 标出的组、术语命中和未决修订。未改组附上原收据。人批准的是候选哈希，不是会话里的一句「可以」。

`review ingest` 成功后，owner 只给这一语发正式配音资格。9 月 23 日西语和韩语听审已经完成，中文未回，整页因此停住。改进后中文可以继续等人，韩语和西语进入各自的 Layer 3。最终汇合仍按已批准的完整清单，不把先完成的语言写成整次交付完成。

用户要求跳过全文人工审核时，写入独立豁免收据，`humanApproval` 保持 false，页面继续披露豁免。豁免不能被 ingest 改写成人工通过。

### 8. 配音

正式渲染的前提是：该语全组通过、候选哈希固定、译文批准或明确豁免、声音授权都有效。缺一组、错哈希或过期声音，渲染不开始。

单元复用核对文本、说话人、声音、checkpoint、种子、参数、政策和音频哈希。未变单元重新合成为 0。改一句就重合成该单元，再重排整轨，因为后面的字幕时间会跟着变。preview 音可以在等人审时准备，正式包仍看批准收据。

计时拆成模型加载、推理、写盘、组装和容器收尾。9 月 30 日 13 条音轨的独立渲染墙钟约 7 分钟一种语言。10 月 1 日 39 条音轨加载了 3 次模型。v8 在 worker 结束后还有约 105 到 130 秒没有叶子。这些空档补上单调时钟记录之前，不增加同 GPU 的并行。

计算主机按现有策略：Spark 是默认的 MFA 和 TTS 主机，Mac 只在已确认的基础设施故障时承接。10 月 1 日诊断固定在 Mac MPS，是因为远程适配器没接上，不是因为内容需要换机器。双讲员沿用播客已经验证的逐单元路由，短样本先走过读者，再提交整篇。

### 9. 回转写

筛查覆盖全部单元。原始 `requires_review` 不改写。相似度用于生成裁定队列。播客里「尼禄」被识别成「麋鹿」，这是待人耳判断的差异，不是自动判配音失败，也不是自动判通过。

人的裁定绑定被听的音频哈希、源单元和决定。音轨哈希一变，旧裁定失效。ASR 起止时间目前缺失，账本里保持 unknown，不用文件修改时间填上。

### 10. 听审与同步

这一步是人工时间的下限。整轨第一次发出，或排程变化会影响相邻句时，人按 1 倍速听当前音轨，并处理队列里的疑点。9 月 23 日三分钟片段的机器疑点是中文 2、韩语 6、西语 3 组，放行条件仍是全文。播客音轨长 3804 到 4609 秒，三种语言各听一遍就是数小时。CLI 在听审前标出与原片的时长差，让人知道超时发生在哪些单元。

音轨哈希未变、整轨听审收据已绑定、只有筛查疑点时，人只裁定疑点。owner 不把「试听了 20 秒」写成整轨通过。

### 11. 发布与读者

组装读取已批准的音轨包。发布前核验完整基线。10 月 1 日基线约 335 个用户文件、2.05 GB，旧的 301 文件快照会漏掉后来的资产。过期快照直接拒绝。已有的四路 HTTP 核验用来比较同一候选的墙钟，失败的文件不产生通过收据。

发布结果分列：

- 资源已上传，读者还不能从列表进入：播客第一次部署就是这种。状态停在资源已部署。
- 列表可选、页面打开、音频从 0 推进、字幕跟着走、换语后文字和音频一致：在该发布目标上记 `http_verified`。这个结果来自验过的部署版本、来源和读回，不来自一份自带 pass 的 observation。
- 真机、锁屏、耳机、现场：保持 `device=not_checked` 或 venue `not_run`。
- 大纲、默想或缺任一测试端或正式端：完整目标保持 pending 或 partial。Firebase 读者通过不提升成 `dual_production_verified`。

页面同时显示音轨能否播、交付检查是否阻断、HTTP 是否已核验、完整目标还缺哪一项。可播音轨不再掩盖 `incomplete`。

### 12. 停止，以及每周范围之外的任务

当前 manifest 写明的完成范围满足后，owner 停止该范围的新派发，并冻结一份只含收据引用的交接包。海报、流水线修改、文档和 PR 用这份交接包另开任务。9 月 20 日页面交付后，同一 Codex 会话又做了海报和改代码，主任务从约 9890 万 token 增到约 1.06 亿。播客窗口里的 Luna 输入是 393,969,205，其中缓存 387,880,704，与业务 response ID 没有交集。这些都留在各自的任务账本里。

完整目标里的后续生产步骤仍由 owner 执行，只是不和工程会话混在同一次上下文里：

| 任务 | 何时跑 | 失败或未做时的状态 |
|---|---|---|
| 大纲、默想 | 已有正式译文之后。生成、结构校验、来源引用和审核都要有 | 缺项就标缺项。不空填。完整目标保持 partial |
| 双测试端人工查看 | 同一候选哈希交给 iOS Beta 和 Firebase Dev | 一端通过不代替另一端 |
| iOS 正式与 Firebase 正式内容 | 两个测试端都通过之后，分别发布和读回 | 一端失败保持 partial。内容晋级不要求当周提交新的商店二进制 |
| PDF | 有人明确要求时 | 失败不重跑音轨和页面。修 PDF 不改变四项产品身份 |
| 设备与现场 | 有单独验收窗口时 | 记录 `not_run`，不把内容发布改成失败 |
| 换初译模型 | 盲评修订分钟和关键错误率有对照之后 | 正式路径保持 Astra 初译、Sol 复核 |

## 失败时停在哪里

| 发生的事 | 停在 | 继续时不重做 |
|---|---|---|
| 预检缺身份、读上限、模块或预算 | `run submit` 之前，状态 `blocked` | 还没有付费父运行 |
| 转写或翻译结果未知 | `waiting_reconciliation` | 不发新请求。对账找到原响应后走 cache-recover |
| 第一组系统性 4xx | 该语机器链 | 其他语继续。该语其余组不派发 |
| 一组语义或插件失败 | 该组新修订 | 未受影响组 `fresh_api_attempts=0` |
| 源文本或锚点内容变了 | 全部语言的正式资格 | 未变的媒体和对齐可复用。旧批准不自动继承 |
| 只有主机名或临时路径变了 | 不停止内容资格 | provenance 追加一笔。缓存和人审仍有效 |
| 被调用的适配器或校验依赖变了 | 新派发 | 历史产物保留。不兼容则 blocked，新增付费为 0 |
| 一个单元声音输入变了 | 该单元重合成，整轨重排 | 其他单元重新合成为 0 |
| 上传或 HTTP 失败 | 发布步骤 | ASR、翻译、TTS 新增调用为 0 |
| 一种语言的译文还没批准 | 该语的正式配音 | 其他已批准语言进入配音 |

## 和设计 8 类的对应

顺序不改。这一份只把验收写进已有步骤：预检夹具在 1.1–1.3，复用计数在 5.4 和 7.4，会话停止在 8.1，canary 与完整目标的区分在 4.8–4.10，审核队列在 2.3 和 4.5，三语重叠仍留在 6.4 之后。跨层追加审核里的 App 依赖闭包、可信发布收据、内容日期映射和多 run 日志，仍按那份文件的 N2–N5 执行。实施仍先做无付费的 A–D 与最小日志。授权过的单语 canary 可以先走完上表里属于该 scope 的步骤，再进入大纲、默想和双端验收，然后才测量多语重叠。
