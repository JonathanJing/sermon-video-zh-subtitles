# MacBook 与 DGX Spark 分层任务耗时比较

实测日期：2026-10-01（America/Los_Angeles）。这是同片段、不同本地运行配置的组件 A/B，不是正式四层生产或质量晋级。模型计算、启动、网络和交付处理分别记录；所有本轮数字来自实际推理与文件操作。

## 主要结果

| 任务 | MacBook 秒 | Spark 秒 | 计时边界 |
|---|---|---|---|
| Layer 1 ASR 30 秒音频 | 1.115 | 0.914 | 模型已加载，纯推理，3 次中位 |
| Layer 3 Qwen3-TTS 1.7B 同一句中文 | 7.045 | 1.328 | 模型已加载，纯推理，3 次中位 |
| Layer 2 Hy-MT2 1.8B Q8 | 1.263 | 0.633 | 模型已加载，早期 nonce 变化，3 次请求中位 |
| Layer 2 Qwen3.5 4B Base BF16 | 3.281 | 1.749 | 模型已加载，早期 nonce 变化，3 次请求中位 |
| Layer 2 Qwen3.5 9B Base BF16 | 5.327 | 3.516 | 模型已加载，早期 nonce 变化，3 次请求中位 |
| Layer 4 小交付包 | 0.070 | 0.562 | 单次新进程发送至 receipt 返回，4 次中位 |

这些行的边界不同：ASR/TTS 是纯推理；翻译是已驻留服务的客户端发送至完整返回；Layer 4 是新进程或新 SSH 会话。不能把这张表直接相加成每周四层耗时。

## 机器与输入

MacBook 为 Apple M1 Max、10 核 CPU、32 核 GPU、64 GB 内存；Spark 为 NVIDIA GB10、20 核 ARM CPU，观测 Linux 可用总内存约 121.7 GiB。ASR/TTS 的 Spark 容器限制为 4 CPU、12 GiB；翻译服务器使用 20 CPU 线程和 CUDA。原有 8000 服务保持运行，实验翻译服务独立使用 18082，并在每个模型结束后回收。两机推理按任务顺序运行，未并发测量。

Layer 1 取现有 `artifacts/gemini-prosody-poc/20260917/A.wav` 的前 30 秒。Layer 2 取已审 2026-09-20 短片的 `block-15-u001` 至 `u005` 五个锚点，共 43 个按空格分开的词；同一英文与同一有效 prompt 在两机配对。Layer 3 使用已有已审语音 job 的第 55 单元「这话是真实的。阿们！」。Layer 4 使用既有 138 秒短片第一组中文内容/字幕和 10.32 秒 WAV，总输入 497,273 字节。媒体与候选均留在忽略目录。

## Layer 1 和 Layer 3 的阶段耗时

| 层 | 机器 | 精度 | 导入秒 | 独立 hash 秒 | 加载秒 | 首次推理秒 | 热推理中位秒 |
|---|---|---|---|---|---|---|---|
| L1 | macbook | MLX 8bit | 0.778 | 0.605 | 1.282 | 0.921 | 1.115 |
| L1 | spark | bfloat16 | 7.299 | 2.943 | 14.567 | 4.268 | 0.914 |
| L3 | macbook | float32 | 7.043 | 4.975 | 3.598 | 7.485 | 7.045 |
| L3 | spark | bfloat16 | 5.071 | 5.239 | 24.761 | 4.027 | 1.328 |

ASR 两机输入 WAV 的 SHA 相同；MacBook 是 Qwen3-ASR 0.6B 的 MLX 8bit 转换，Spark 是官方 BF16，模型权重哈希不同。ASR 外部读入分别为 0.002/0.006 秒；提供者内部特征处理与解码仍包含在推理计时内。

TTS 使用 Qwen3-TTS 1.7B 的讲员 checkpoint。两机主 checkpoint SHA 都是 `3b46fc0f5268c3bf14c55c0b11833125fbacc31c6a7ae8b7f1328a227ef8a4d0`；MacBook 用 MPS float32，Spark 用 CUDA BF16。生成音频分别为 2.56/2.16 秒，热推理中位/音频时长约 2.752/0.615；结果精度、运行时和音频长度不同，因此 7.045/1.328 的比值不是纯硬件加速比。所有输出非空、有限、非零，完整解码通过；没有人听审。

### 派发和传输

| 层 | Mac 本地四次整批秒 | Spark SSH 准备秒 | 输入 SCP 秒 | Spark 四次执行与回执秒 | 音频或文件下载秒 |
|---|---|---|---|---|---|
| L1 | 6.957 | 0.625 | 0.598 | 35.415 | 0.786 |
| L3 | 44.881 | 12.544 | 0.768 | 45.582 | 1.186 |

上述 ASR/TTS 执行都是一次新进程内的首次加三次热推理，共四次。Spark 执行包含 SSH 会话、Docker/Python 启动与回执返回。该批次的派发总数不能当作单次；准确的单次回执已通过下面独立补测取得。L3 准备的 12.544 秒是本轮观测慢项，未诊断其原因。

### 一次请求发送到完整结果

| 任务 | 导入秒 | 输入读取秒 | 模型加载秒 | 单次推理秒 | 保存秒 | 发送至完整回执秒 | Mac 本地产物可用秒 |
|---|---|---|---|---|---|---|---|
| macbook-asr | 0.420 | 0.004 | 1.278 | 1.050 | 0.001 | 2.875 | 2.875 |
| spark-asr | 6.947 | 0.004 | 13.343 | 4.177 | 0.000 | 26.249 | 28.644 |
| macbook-tts | 5.337 | 0.000 | 8.350 | 9.182 | 0.004 | 22.972 | 22.972 |
| spark-tts | 4.270 | 0.000 | 26.919 | 3.336 | 0.007 | 35.896 | 38.605 |

每行只执行一次推理，输入已在目标机就位；不包含第一次传入输入或上传脚本。Spark 从 Mac 新发 SSH/Docker 任务，到父进程收到已保存结果的 JSON 事件计时。ASR 回执含完整文字；TTS 回执确认远端 WAV 已保存，完整 WAV 取回后的时刻另列。Mac 的文件在本地保存完即可用，无远端下载。模型身份沿用之前逐文件 hash 回执，本轮仅读回身份收据并重检输入 hash，没有重复数 GB 权重 hash。

阶段列均为同一次新进程的计时，合计与回执总时长的差还包含进程、SSH、Docker、回执处理等开销，不是独立测得的排队。单次补测和前一批的加载数字不同，分别保留实际观测；未清除 OS 文件缓存，不能用单样本给冷启动分布排名。

## Layer 2 翻译的阶段耗时

| 模型 | 机器 | 输入处理秒 | 逐 token 生成秒 | 发送至首内容秒 | 发送至完整返回秒 | 三次输出 token 数 |
|---|---|---|---|---|---|---|
| Hy-MT2 1.8B Q8 | macbook | 0.105 | 1.099 | 0.115 | 1.263 | 59,59,59 |
| Hy-MT2 1.8B Q8 | spark | 0.019 | 0.563 | 0.049 | 0.633 | 60,63,63 |
| Qwen3.5 4B Base BF16 | macbook | 0.651 | 2.602 | 0.678 | 3.281 | 45,45,45 |
| Qwen3.5 4B Base BF16 | spark | 0.108 | 1.564 | 0.188 | 1.749 | 45,45,45 |
| Qwen3.5 9B Base BF16 | macbook | 1.546 | 3.708 | 1.588 | 5.327 | 42,42,42 |
| Qwen3.5 9B Base BF16 | spark | 0.193 | 2.848 | 0.920 | 3.516 | 42,42,42 |

以上各列为各自三次中位数，不能相加还原中位总时长。首次至首内容和总时长都是自同一次发送起算的累计量。输入处理是服务端 prefill，输出生成是 decode。Spark 请求通过已建立的 SSH 隧道，MacBook 请求通过本机 Ollama；两机模型精度相同，运行时不同。温度 0、top-k 1、top-p 1、seed 42、上下文 8192、生成上限 256，所有流都以正常 stop/eos 完成，没有截断。

三次请求在 prompt 早期加入不同 `Timing trial` 编号，英文保持不变，用于减少整段重复命中的 KV 缓存。两机同一编号的有效 prompt SHA 完全一致；仍可能复用很短的前缀，因此不是缓存绝对关闭。Ollama 的 prompt_eval_count 与 llama.cpp 的 prompt_n 口径不同，不据此拼出统一输入 tokens/s。

### 首次请求与重复缓存

| 模型 | 机器 | 首次加载或服务准备秒 | 首请求完整返回秒 | 首请求首内容秒 |
|---|---|---|---|---|
| Hy-MT2 1.8B Q8 | macbook | 1.561 | 2.408 | 1.776 |
| Hy-MT2 1.8B Q8 | spark | 服务准备 1.671 | 0.617 | 0.068 |
| Qwen3.5 4B Base BF16 | macbook | 4.336 | 6.901 | 4.871 |
| Qwen3.5 4B Base BF16 | spark | 服务准备 13.153 | 1.952 | 0.303 |
| Qwen3.5 9B Base BF16 | macbook | 14.912 | 19.233 | 15.387 |
| Qwen3.5 9B Base BF16 | spark | 服务准备 29.902 | 3.915 | 0.951 |

Mac 的首请求总时长包含 Ollama 模型加载。Spark 先启动独立服务，再发送首请求；“服务准备”包含 SSH 启动、模型加载和轮询等待，不能冒称纯加载时长。Spark 首次的从启动到结果可将同一轮这两段顺序时长相加，但不包含之前的 hash 与环境准备。文件 hash 可能预热 OS 缓存，因此这些首轮都不是冷盘缓存实验。

重复完全相同 prompt 的三次热请求中位：

| 模型 | 机器 | 请求完整返回秒 |
|---|---|---|
| Hy-MT2 1.8B Q8 | macbook | 1.007 |
| Hy-MT2 1.8B Q8 | spark | 0.538 |
| Qwen3.5 4B Base BF16 | macbook | 1.991 |
| Qwen3.5 4B Base BF16 | spark | 1.731 |
| Qwen3.5 9B Base BF16 | macbook | 4.632 |
| Qwen3.5 9B Base BF16 | spark | 3.795 |

Hy-MT2 两机 GGUF SHA 完全相同。Qwen 4B/9B 两机 GGUF SHA 不同，本轮保留各自真实本地导入产物；这是运行配置比较，不能标为相同字节权重的硬件对照。量化、模型 hash、prompt hash、运行时与逐次原始计时见机器可读 evidence。

### 客户端发送和未归因时间

| 模型 | 机器 | JSON 序列化 ms | 本地 TCP 连接 ms | socket 提交 ms | 末内容至流结束 ms | 未归因剩余 ms |
|---|---|---|---|---|---|---|
| Hy-MT2 1.8B Q8 | macbook | 0.030 | 0.383 | 0.151 | 17.471 | 6.677 |
| Hy-MT2 1.8B Q8 | spark | 0.008 | 0.202 | 0.051 | 2.946 | 42.031 |
| Qwen3.5 4B Base BF16 | macbook | 0.027 | 0.313 | 0.105 | 54.234 | 25.294 |
| Qwen3.5 4B Base BF16 | spark | 0.009 | 0.221 | 0.078 | 0.122 | 72.702 |
| Qwen3.5 9B Base BF16 | macbook | 0.023 | 0.300 | 0.127 | 137.864 | 38.514 |
| Qwen3.5 9B Base BF16 | spark | 0.009 | 0.233 | 0.065 | 74.320 | 474.999 |

socket 提交只证明写入本地 socket，不证明远端已经收到；Spark 的 TCP 连接是连到本机 SSH 转发端口，不能当成整个 LAN 链路的建立时间。末内容至流结束包含最终计时回执与结束处理。未归因剩余为逐次总耗时减输入处理、生成和可测加载后的中位数，混合网络、调度、队列、序列化等；它不是额外可求和的独立阶段，也不能称为纯网络或排队耗时。没有单向网络上传/下载的服务端时间戳。

## Layer 4 确定性交付处理

| 机器 | 读取 ms | 输入 hash ms | 解析解码 ms | 聚合序列化 ms | write 与 fsync ms | 读回核验 ms | 处理总 ms |
|---|---|---|---|---|---|---|---|
| MacBook | 0.142 | 0.217 | 0.044 | 0.043 | 0.584 | 0.350 | 1.357 |
| Spark | 0.152 | 0.202 | 0.150 | 0.026 | 6.841 | 0.362 | 7.734 |

这层没有本地模型。两机包、回传 WAV 及所有轮次 readback 都验证一致。新进程的单次发送至 receipt 返回中位为 MacBook 70.382 ms、Spark SSH 562.271 ms，先前已上传的输入传输不含在内；独立 SCP 上传 862.695 ms，打包音频和结果下载 665.003 ms。SSH 握手和进程启动对这个小任务明显；这是确定性 microbenchmark，不含正式 Release Package 的资格门禁、HTTP 发布或客户端播放。不同 OS 的 fsync 行为不能用于给 GPU 或物理磁盘排名。

## 如何使用这些结果

本轮配置下，小型 ASR 的热推理差距较小；配音的 Spark 热推理更快，但大模型加载和任务启动可能抵消短任务收益。驻留模型可以避开重复导入与加载，是否改善真实生产要对生产调度路径再测。翻译已记录客户端完整往返，但不能将端到端剩余时间拆成网络、排队或服务调度各自的精确数字；缺少逐请求服务端入队/出队时间，所以排队耗时明确为未知。

此次翻译候选出现可见错误：Qwen 4B 把 “church at Laodicea” 所在句翻成「以弗所书三章16节」，原始 prompt 的 Qwen 9B 首轮则写了「以弗所教会」。nonce 版本的 9B 改为「老底嘉的教会」，表明即使英文相同，微小 prompt 变化也会影响候选。没有进行全量盲审或质量评分，全部输出仍是实验候选。

每个热测条件三次；Layer 4 独立请求四次，不报告 P95、负载并发或整篇吞吐；没有清空 OS 文件缓存。ASR、TTS、打包和翻译使用各自片段，并非同一片段穿过正式四层链路。本次未改审批、正式产物、发布目录或线上服务，没有设备或现场验收结论。
