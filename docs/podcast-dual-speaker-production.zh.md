## 和单讲员周更的差别

| 环节 | 单讲员周更 | 双人播客另加的要求 |
|---|---|---|
| 来源范围 | 人工给出证道起止 | 人工给出节目正文起止；片头片尾音乐不进窗口 |
| 说话人 | 不需要 | 独立的说话人区分产物，加上人工把匿名标签对到真人的映射收据 |
| 锚点 | 按句与停顿切 | 每个英文单元只能属于一位讲员；跨换人的单元必须在换人处切开 |
| 英文审核 | 完整性、词时间、句界、停顿 | 另加说话人归属，以及抢话、附和声的处理 |
| 翻译 | 逐组初译、复核 | 冻结的政策写明是否把说话人标签放进上下文；术语插件覆盖本期的专业词 |
| 音色 | 一个讲员 | 每位讲员在每种语言都要有授权和能力证据；缺一位就不能正式配音 |
| 配音 | 一个 adapter；Spark 8×8 | 逐单元路由到对应讲员；按英文原顺序排程 |
| 音频包与发布 | 一个 voice | 记录两个 voice 及各自授权；页面讲员栏、AI 配音披露写两个人 |

## 开工前

开工检查按 runbook 的 `check_run_start.py` 执行。双人播客另外先确认以下几项；缺哪一项，只挡住依赖它的环节：

1. **来源与署名。** 只使用公开或用户授权的媒体，记录官方 URL、媒体哈希与时长。页面注明来源；本项目与 Mariners Church 无隶属关系。
2. **系列名。** 节目系列名先登记进[系列名称表](series-terminology.zh.md)，附上名称依据，再开始翻译。登记会改变冻结政策的哈希，必须在冻结 Layer 2 政策之前完成。
3. **讲员音色。** 在 Registry 里逐一查两位讲员在本次各目标语言的授权用途和能力状态。没登记的讲员走下文的「新讲员音色」流程。这件事不挡 Layer 1 和 Layer 2。
4. **发布计划。** 写明目标语言、每种语言用人工审核还是机器质检豁免、只发音频还是也发视频（视频要遵守发行合同的文件数配置），以及多语言页面要不要等齐了再一起发。
5. **预算。** 按运行配置为当前阶段写预算文件。付费阶段没有已批准的预算就不派发。

## Layer 1：英文源文、说话人与锚点

### 1. 窗口与英文转写

- 窗口由人工批准；片头片尾的纯音乐和赞助口播是否进窗口，由操作员明确决定并写进收据。
- 英文转写与词时间走正式入口：`tools/ops/run.py source.unified_stage` 加上既有 MFA，按计算策略 Spark 优先。不用说话人区分模型输出的文字代替正式 ASR。正式 ASR 若返回说话人轮次，只是按每个 180 秒分块各自编号的匿名标签，不能跨分块判断是不是同一人；整期的说话人归属由下面的独立说话人区分提供。

### 2. 说话人区分

- 说话人区分是独立产物，每次运行冻结模型、版本、精度、主机和参数，原始输出不可修改。2026-10-20 的试跑（[运行报告 PR #1226](https://github.com/JonathanJing/sermon-video-zh-subtitles/pull/1226)）中，VibeVoice-ASR 原版 BF16（Spark）和 MLX 8bit（MacBook）的说话人标签逐帧一致率 99.66%，可以作为候选 producer。默认主机仍按计算策略选 Spark；要改用 MacBook 当默认，需要另做政策决定。
- 输出只带匿名标签（例如 `0`、`1`）。模型返回的姓名、节目里的自我介绍、视频标题都不能单独确定真人身份。
- 用同一份英文音频，转成该模型需要的采样率后再跑。不降噪，不调音量，转换命令和输出哈希都记下来。

### 3. 人工说话人映射

- 从每个匿名标签各截两段以上干净样本（不同时段各一段），连同开场一起给操作员听。操作员写一份映射收据，把每个标签对到 Registry 里的 `speakerId`，或者标为 `unknown`。
- 映射收据绑定说话人区分产物的哈希。区分重跑或模型变化后，映射要重新确认；产物不变时沿用原收据。
- 某个标签标为 `unknown` 时，这位讲员的单元不能正式配音。

### 4. 每个单元只属于一位讲员

- 把说话人区段和 MFA 词时间求交集，给每个英文单元确定一位讲员。一个单元里出现换人时，用锚点 `boundaryOverrides` 在换人处切开；不能为了凑句子把两个人的话拼在同一个单元里。
- **抢话与附和声。** 对方说话时插进来的短附和（"yeah"、"right"、"mm-hm" 这类）照原样保留在英文里，单独成单元，并标为附和类。它在 Layer 3 怎么处理见下文「待决定事项」第 2 条。双方同时说完整句子的重叠段，进入英文审核队列，由人决定归属和先后顺序。
- 归属置信度不够的单元（重叠占比高、标签在单元内来回跳）进入审核队列，不自动定案。

### 5. 冻结前的交叉核对

翻译前一次性汇总三份英文的差异：正式 ASR、说话人区分模型自带的转写，以及 YouTube 等平台的自动字幕（如有）。按专名、经文出处、神学术语、数字和引语排出有限的复核清单，每条附上前后文和音频片段。2026-10-20 的试跑里，两份自动转写都把前千禧年、无千禧年等末世论术语听错过，这类词必须进清单。源文有争议时回到原音频裁定，裁定生成新 revision，保留原 ASR。

### 6. 输出

- English Source Package 和锚点照常生成，schema 不改。
- 说话人归属写在单独的**说话人路由**文件里，绑定源包、锚点、说话人区分产物和映射收据的哈希。它是 Layer 1 的产物：路由改变时，源包身份不变，但依赖路由的 Layer 3 要作废。
- 英文人工审核在同一轮里加审说话人归属；审核收据绑定路由文件的哈希。

## Layer 2：翻译

- 按语言走 canonical controller 和现行模型策略；初译、复核、语言插件、候选准入、自动修复、回译质检和精简的规则都不变。
- **说话人上下文。** 冻结政策时写明是否把讲员标签放进翻译和复核的上下文（用来判断"你""我"的指代和称呼）。这个选择进入政策哈希；中途改动等于新政策。
- **术语。** 为本期建一个只在本期范围内生效的术语插件，覆盖节目里的专业词，例如末世论各派名称、"但以理的第七十个七"。经文按已批准的精确引用范围处理。插件绑定本期源包，不能直接拿到别的节目用。
- 审核方式按发布计划：人工全文审核，或者按[机器质检豁免](machine-quality-waiver.zh.md)签发译文豁免（`humanApproval=false`，页面显示披露）。
- 翻译不等音色。新讲员的音色训练和能力试听与 Layer 2 并行。

## 音色

### 已登记的讲员

本次目标语言在 Registry 里是 `human_reviewed`、且授权用途覆盖本次用途的，直接复用固定的 checkpoint，每期不重新选声、不重做能力试听。每期仍要为每位讲员、每种语言签发正式音频授权（`sermon-source-voice-authorization-v2`），绑定本期源包、候选和 checkpoint。

### 新讲员音色

1. **授权。** 用户明确说明这位讲员的声音可以用于训练和配音，并写明适用的语言与用途。记录为一份用户声明（`sermon-source-user-voice-attestation-v2` 或训练用途的对应记录），写进 Registry 的 `authorization.evidence`。没有这份授权，不训练、不克隆。
2. **训练素材。** 按[训练数据规范](../experiments/sermon-dubbing-poc/TRAINING.zh.md)准备：只用映射收据确认属于这位讲员、不重叠、没有音乐的干净片段；英文录音配 Layer 1 的英文逐字稿；按整期节目划分训练、验证和测试集。只有一期素材时，结果只能算训练工程 smoke，不能证明泛化，应尽量补充同一讲员的其他节目。
3. **训练与登记。** 在 Spark 上训练单讲员 checkpoint，然后在 Registry 新增条目：`speakerId`、`speakerKey`、权重 SHA-256、基座模型版本和训练回执。私有素材和权重不进 Git。
4. **各语言能力。** 用统一试听文稿为每种目标语言生成试听，经 ASR 筛查后由人工逐语言听审，通过的语言才改为 `human_reviewed`。能力状态不能跨语言继承；某种语言没通过，这位讲员在该语言就不能正式配音。
5. **没有就绪时。** 不能借另一位讲员的音色或基座默认音色顶替。发布计划可以选择等待，也可以让该语言以 `audio_unavailable` 只发文字。

## Layer 3：双人配音

- **Speech job。** 每种语言一份 job，每个单元带 `speakerId`。按讲员分 worker，每个 worker 绑定自己的 adapter、checkpoint、授权和能力收据，并按说话人路由核对单元归属。路由、任一讲员的 checkpoint 或授权改变，job 都要作废重建。
- **合成。** 每个单元用所属讲员的音色、自然语速合成一次；不变速，也不在句子中间拼接。每位讲员按自己的 worker 批处理；排程按英文原顺序合并两人的单元。原音里两人同时说话时，目标语言的音轨改为先后播放，由既有确定性排程决定起点，不做混音叠放。
- **时长预算与精简。** TTS 前的时长预算按讲员分别拟合语速；预算身份同时绑定两个 adapter。精简规则不变。
- **质检与听审。** 单句和整轨质检照常。逐单元收据记录讲员和 checkpoint，整轨核对还要检查每个单元用的音色是否等于路由指定的讲员。抽查样本必须覆盖两位讲员。豁免的比例规则按全篇统计，不分讲员。
- **音频包。** 记录每个 voice 的讲员、checkpoint、各语言能力和授权哈希，以及说话人路由哈希。

## Layer 4：发布

- 每种语言照常一个 Release Package。机器质检豁免的语言用 release v4 和 catalog v4。页面类别为播客。
- 讲员栏写两位讲员的姓名。页面注明两个人的声音都是 AI 配音，并显示各自的审核状态。
- 是否附带视频按发布计划和发行合同；默认只发音频和字幕。
- 海报按[每周海报交付](tongxing-weekly-release.zh.md#每周海报交付)，在页面通过 HTTP 核验之后制作。没有用户的指示，不发送或上传海报。

## 运行报告

每次正式运行或测试结束，无论成败，都按[运行报告](test-run-retrospective.zh.md)导出脱敏报告并开仅含文档的 PR。双人播客的报告另列：说话人区分的模型与主机、映射收据、按讲员统计的单元数与时长、每位讲员的音色身份，以及附和、重叠类单元的处理结果。

## 现有代码的缺口

本页规定的是合同；截至 2026-10-21，dev 上还缺下面这些实现。实现时按版本化 schema 加迁移，保留旧产物可读。

| 需要的能力 | 现状 | 跟踪 |
|---|---|---|
| 说话人区分作为 Layer 1 的独立 producer，以及映射收据 | 只有 2026-10-20 的试跑脚本，不在仓库里 | 新增项（待登记） |
| 说话人路由和按讲员切锚点 | `codex/stage2-activation-packet` 上有 `sermon-podcast-speaker-route-v1`；dev 上没有 | `DEV-L3-001/004`、`DEV-DIAG-017`（复盘 F01、R06） |
| 多讲员 speech job、双 worker 渲染、播客音频包 | 同一分支上有 job v3/v4-podcast、dual-worker manifest、audio package v2/v3-podcast；dev 的 renderer 和 Spark 8×8 路径都拒绝多讲员 | 同上 |
| 按讲员拟合语速的时长预算 | `predicted_schedule` 只绑定一个 speech job 合成身份 | 新增项（待登记） |
| 质检校准覆盖两个音色 | 校准按单一音频身份设计 | `DEV-L3-001` |
| Layer 4 播客页的两讲员披露 | 上一期用一次性 Dev 适配完成，没有正式入口 | `DEV-L4-006`（复盘 R07） |

这些缺口补上之前，双人播客能按本页走完 Layer 1 和 Layer 2；正式的 Layer 3 和 Layer 4 要等相应实现合并并通过测试，不能拿分支上的一次性脚本当正式 producer。

## 待决定事项

下列选择会改变结果或支出，要由用户决定，并在做出决定的那次运行里记录：

1. **说话人区分的默认主机。** 计算策略默认 Spark；试跑里 MacBook 8bit 更快，结果几乎相同。建议：在 Spark 没有其他驻留模型时复测一次再定。
2. **附和声的配音方式。** 选项：A. 全部配音，计入排程；B. 只出字幕不配音，单独计数，不计入豁免的"不配音超过 5%"规则；C. 按时长预算决定，放不下的转为只出字幕，并计入 5% 规则。B 会改变机器质检豁免的现行规则，需要先修改那份文档。建议 C，因为它不需要改现行规则。
3. **翻译是否带讲员标签。** 建议带上，用来判断指代；这会改变政策哈希。
4. **新讲员音色先覆盖哪些语言**，以及没有就绪时，该语言是等待还是只发文字。
